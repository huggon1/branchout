# Worker

本文描述 Agent 工作进程的目标职责与文件分工。运行边界见[架构总览](../../docs/architecture-overview.md)，任务字段和结果状态见[数据与消息契约](../../docs/data-contracts.md)。

## 职责与任务

`worker` 接收主进程交付的任务输入，创建独立 Pi 会话，调用所需的仓库与平台读取能力，并向主进程报告阶段、结果和失败状态。每个任务拥有独立会话上下文；主进程决定任务与工作进程的分配。

- **项目图生成**：读取本机 Git 项目的当前文件，形成含未提交修改的输入快照；按方向生成 UI/UX workflow 图或功能模块 architecture 图，接入 Archify 的图源校验与交互工件，再补充每个节点的简述、代码事实、可分析性和分析说明。
- **节点仓库分析**：接收冻结的图版本节点资料和用户指定的公开 GitHub 仓库链接；固定目标提交，读取相关文档与静态代码，按分析说明形成比较点、检查范围、结论及两侧证据。
- **转发理解**：调用平台接入读取链接内容，依据已获取的来源快照生成通用理解。
- **模型支持**：通过 Pi 运行时创建任务会话，查询当前运行时的模型兼容性并处理连接检查。

图生成向主进程交付完整的图版本草稿；仓库分析和转发理解交付带 `taskId`、`resultId` 的素材草稿。主进程校验并保存这些结果。

## 依赖

`worker` 使用 `shared` 的任务与素材契约、Pi 的模型调用能力、Archify 的图生成能力，以及 `platforms` 的转发读取能力。仓库读取工具分别处理本机项目快照与目标仓库固定提交。任务所需模型执行配置由主进程提供，在受控执行边界内使用。

## 目标文件分工

- `main.ts`：接收和校验主进程命令，分发任务并回传工作进程事件。
- `project-worker.ts`：组织项目图生成与节点仓库分析任务。
- `forwarding-worker.ts`：组织来源读取与通用理解。
- `model-worker.ts`、`pi-runtime.ts`：执行模型连接检查、兼容性查询和每任务 Pi 会话创建。
- `tasks/`：分别实现项目图生成、节点补充分析与目标仓库比较。
- `tools/repository-tools.ts`：读取本机项目并建立生成图所用的项目状态与文件依据；目标仓库读取工具负责固定提交和定位目标证据。
- `understanding/platform-content.ts`：准备转发内容的通用理解输入。
