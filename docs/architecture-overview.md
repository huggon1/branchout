# Branchout 架构总览

## 技术组合

Branchout 采用 Electron、React 和 TypeScript：

- Electron 提供桌面应用运行环境。
- React 组织和呈现用户界面。
- TypeScript 用于编写 Branchout 应用代码；第三方平台工具可以使用各自适合的技术，不要求使用 TypeScript。
- Pi 是 Agent 框架，用于模型与工具调用循环。

Pi 负责执行模型推理、工具调用及其循环；Branchout 应用负责准备业务输入、决定每类任务可以使用哪些工具，并接收进度和结果完成保存。基线理解、探索和转发共用这套 Agent 执行能力，但每个任务使用独立的 Pi 会话，不共享会话上下文。

## 运行职责

- **界面进程**：展示应用状态并接收用户操作，使用 React 组织界面。
- **Electron 桌面主进程**：管理窗口、后台任务和本地数据。关闭窗口后主进程继续保留正在运行的后台任务。
- **Agent 工作进程**：读取项目，调用平台工具，执行搜索与内容理解，并把进度和结果交给桌面主进程保存。

界面进程重新打开时，从桌面主进程和本地数据读取当前任务状态。探索与转发可以同时推进，具体并发数量由实现控制。

独立 Pi 会话是任务上下文边界，不代表每个任务需要独立进程。三部分运行职责与具体任务数量、会话数量之间没有一一对应关系。

## 模型连接与凭据

桌面主进程拥有唯一的当前模型连接及其凭据边界。界面进程只能读取脱敏后的连接状态，并通过 preload 的受控接口提交配置或发起登录；它不能读取已经保存的 API Key、访问令牌、刷新令牌或认证文件。Agent 工作进程只接收完成当前执行所需的连接参数，不拥有连接配置的持久化，也不能把凭据写入任务消息或结果。

通用 API 由主进程保存服务地址、接口类型、模型标识和受保护的 API Key。首版只把 `openai-responses` 与 `openai-completions` 注册为 Pi 的明确 API 类型；其他 Pi 支持的接口、自定义流式实现和仅声称兼容的服务不在首版范围内。API Key 使用操作系统保护的本地凭据存储，不以明文进入普通应用数据。

Codex 订阅账号使用 Codex 官方登录流程及其凭据存储，不由 Branchout 自行解析或向界面暴露令牌。登录后，主进程通过 Codex 客户端查询当前可用模型，再校验所选模型能否由当前 Pi 运行时执行。账号或客户端返回的模型列表是可选项来源；Pi 自带或缓存的模型目录只用于运行兼容性判断和必要的离线元数据，不能证明某个账号有权使用该模型。登录完成和用户主动刷新时重新查询模型列表；查询失败必须保留真实失败状态，不能用静态目录伪装为账号查询结果。Codex 客户端作为登录和模型查询适配层，必须在实现阶段通过集成验收后才能视为可用。

主进程在创建基线、探索或转发任务时，取得当前连接的执行快照并交给该任务的独立 Pi 会话。之后保存的新连接只供新任务使用，已经运行的任务继续使用自己的启动快照。替换连接时，旧凭据只保留到最后一个使用它的运行任务结束，不作为历史连接无限期保存。连接摘要与秘密字段的跨进程边界见 [数据与消息契约](data-contracts.md#模型连接与凭据边界)。

技术依据：[OpenAI Codex 认证](https://learn.chatgpt.com/docs/auth)、[OpenAI Codex 模型](https://learn.chatgpt.com/docs/models)、[Pi Providers](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/providers.md) 与 [Pi Custom Models](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md)。

## 逻辑模块职责

- **项目与基线**：管理本机 Git 仓库，以及每个项目独立的产品基线和 UI/UX 基线。
- **探索方案与执行**：按用户选择的方向，使用对应基线和预设方案编排搜索、筛选与逐条理解。
- **转发接入**：接收用户提交的链接，将其交给共用的平台与理解能力处理。
- **平台接入**：提供平台搜索、详情读取、配置和能力状态，是探索与转发共用的来源边界。
- **内容理解**：生成平台通用理解，并在探索场景中生成独立的项目参考信息。
- **素材存储**：保存每次进入系统的独立素材记录，以及正文、媒体、总结和上下文元信息。
- **界面与阅读**：承载项目配置、基线维护、探索发起、素材列表和单条阅读体验。
- **Agent 执行能力**：封装 Pi 会话、模型与工具调用，支撑基线生成、探索和内容理解，并由应用控制业务输入、工具授权与结果交付。

这些逻辑模块表达业务职责，不等于独立进程或代码包，也不要求与上述三部分运行职责一一对应。

源码目录与关键文件职责见 [源码目录蓝图](../src/README.md)。

上述模块之间的平台输出、理解结果、素材保存和任务消息边界见 [数据与消息契约](data-contracts.md)。

## 主要协作流程

用户在界面进程发起探索后，桌面主进程创建并管理后台任务。Agent 工作进程读取项目和对应方向的基线，通过“探索方案与执行”调用“平台接入”完成多平台搜索和读取，再调用“内容理解”生成通用理解与项目参考。工作进程持续把进度和结果交给桌面主进程，由“素材存储”保存为独立记录；界面进程从主进程读取最新状态并通过“界面与阅读”呈现。缺少基线时，流程先通过“Agent 执行能力”生成对应基线，再继续本次探索。

探索运行期间，桌面主进程可以接收新的链接转发并交给 Agent 工作进程解析，不需要等待探索结束。链接转发由“转发接入”接收链接，复用“平台接入”读取内容，再由“内容理解”生成通用理解，最后由桌面主进程通过“素材存储”保存并交给“界面与阅读”呈现。转发流程不经过项目基线，也不生成项目参考。
