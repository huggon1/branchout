# Branchout 架构总览

本文描述目标架构。产品行为以[产品规格](product-spec.md)为准，跨模块字段与任务消息以[数据与消息契约](data-contracts.md)为准。

## 技术组合与运行边界

Branchout 使用 Electron、React 和 TypeScript 构建桌面应用。Pi 承担模型与工具调用循环；每次项目图生成、仓库分析和转发理解使用独立的 Agent 会话。Archify 为项目图提供结构化图源、校验与动态可视化能力。它的[交互式 HTML 与图源机制](https://github.com/tt-a1i/archify#how-it-works)由 Branchout 集成到工作区。

- **界面进程**呈现方向工作区、项目图、节点侧栏、任务状态与素材阅读，并通过受控接口向主进程提交操作。
- **桌面主进程**管理窗口、模型连接、后台任务和本地持久化。窗口关闭后，任务继续由主进程管理；重新打开窗口时，界面读取任务与素材状态。
- **Agent 工作进程**执行项目读取、图生成、节点补充分析、目标仓库分析和转发内容理解，向主进程交付进度与结果。每个任务拥有独立会话上下文；主进程安排任务与系统进程。

主进程持有可写的应用状态，并校验界面进程与 Agent 工作进程提交的消息。Archify 生成的交互内容在隔离视图中呈现；节点选择等事件经校验后进入界面状态。隔离视图只接收展示所需的图数据。

## 项目图生成

项目图生成器按项目和方向建立一次输入快照，读取本机 Git 仓库的当前文件，包括尚未提交的修改，并记录可追溯的项目状态。UI/UX 方向将用户任务中的步骤与转移组织为 workflow 图；功能模块方向将产品能力与关系组织为 architecture 图。两种图都由静态代码与文档分析支撑，再交给 Archify 生成和校验图源与可视化结果。

Archify 的原生仓库证据校验面向固定提交的 architecture 图；workflow 图及本机未提交修改的证据由 Branchout 的项目快照和节点资料承担。节点补充分析在同一次快照上完成，给每个节点形成简述、事实与依据、可分析性判断，以及适合分析节点的固定分析说明。[Archify 仓库证据契约](https://github.com/tt-a1i/archify/blob/main/archify/references/authoring-contract.md#repository-evidence)是这一边界的技术依据。

主进程把通过校验的图源、交互工件、节点资料与项目状态作为一个不可变图版本保存，并将其设为该方向的当前图。手动重新生成创建新版本；关联旧版本的素材继续读取原图与节点资料。项目解绑只移除可选项目，本地持久化层按素材引用关系保留历史图版本。

## 基于节点的仓库分析

节点分析任务接收一个冻结的图版本、节点资料和用户输入的公开 GitHub 仓库链接。工作进程以保存的节点事实为本项目依据，在隔离的目标仓库读取区域固定提交并读取相关文档与静态代码。

分析器先定位目标仓库中的对应做法，再按分析说明组织本项目做法、目标做法、差异和各自的证据。没有找到对应功能、检查范围不足及读取失败分别作为可区分结果返回。主进程保存每次任务的素材及来源定位信息；素材中的图版本、节点与目标提交在后续重新生成图或再次分析同一仓库时保持原指向。

## 转发与素材

应用内添加链接、飞书和 Telegram 的入口汇入转发接入模块。平台接入负责读取链接指向的内容并报告获取范围；内容理解模块生成与来源正文分离的 AI 通用理解。主进程保存每次转发形成的独立素材。

素材存储为转发素材和节点分析素材提供统一列表与阅读数据。图版本及节点资料、目标仓库提交与文件依据、来源正文与图片等由各自任务交付，主进程统一校验并持久化。界面从主进程保存的记录读取历史素材。

## 模型连接与凭据

主进程拥有唯一的当前模型连接及受保护的凭据。界面只读取脱敏状态，通过 preload 受控接口提交配置或发起登录。工作进程仅获取当前任务执行所需的连接快照；连接变更供后续任务使用。

通用 API 的 API Key 使用操作系统保护的本地凭据存储。Codex 订阅账号沿用 Codex 登录与凭据机制；可选模型由当前账号和 Codex 客户端查询，Pi 运行时负责执行兼容性校验。图版本、素材和界面可读任务消息只接收脱敏状态。
