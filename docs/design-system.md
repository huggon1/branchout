# Branchout 设计系统

本文定义跨页面共用的信息、文案、操作层级和渐进呈现规则。页面任务与流程以 [UX 规格](ux-spec.md) 为准。

## 信息呈现

- 一个界面突出当前任务最重要的信息；同级标题、说明和操作按任务需要安排视觉层级。
- 默认内容帮助用户识别对象、理解状态并采取下一步；补充信息在需要时展开。
- 必要提示和异常状态保持可见。
- 标题和标签帮助用户识别对象。操作可以使用文字、图标或两者组合，以用户能否快速识别动作为准。

## 文案

- 使用文字的操作直接说明动作及对象；仅用图标的操作提供清楚的悬停提示和无障碍名称。
- 状态文案描述实际发生的情况，明确区分未执行、未覆盖、无结果、内容不完整、完整性未知和失败。
- 本项目节点事实、目标仓库做法、比较结论、来源内容和 AI 通用理解使用清楚且一致的名称。
- 提示信息优先告诉用户当前状态和可采取的下一步。

## 操作层级

- 每个任务突出清晰的主要操作；次要操作降低视觉权重，低频操作按需收纳。
- 操作放在其作用对象附近：项目图操作对应当前图，节点分析操作对应选中节点，素材操作对应素材，平台配置对应平台状态。
- 对象明确、图形含义容易识别的操作可只显示图标，例如缩放、侧栏开合、上一条或下一条、展开事实和打开来源。含义需要解释或执行后有重要后果的操作，用文字、提示或确认让用户理解动作。相同动作在各处沿用同一图标与无障碍名称。
- 相同任务的主要操作保持稳定位置和识别方式。
- 用户完成常见任务所需的入口直接可见。
- 主要、次要和轻量操作使用同一套跨页面层级；层级通过位置、尺寸与视觉强调体现。
- 长任务中的完成操作保持在稳定且持续可见的位置；保存、取消和阅读导航固定于操作区域。

## 渐进呈现

- 先显示完成当前步骤所需的信息，再显示解释、配置和细节。
- 展开的内容保持与触发对象相邻，并允许用户回到原来的任务位置。
- 页面层级用于分开不同任务，局部展开用于补充同一对象。

## 项目图与节点侧栏

- 项目图以节点和关系为主视觉。方向、项目、图版本及生成时的项目状态保持可辨，图上的标签优先使用用户能理解的任务或能力名称。
- 图的缩放、平移、节点聚焦和路径查看保留连贯的动态反馈。动效帮助用户追踪位置与关系；尊重系统减少动态效果的设置。
- 悬停提示节点身份，选中状态在图中持续可见，并与右侧侧栏标题对应。选中节点及其相关路径突出显示，其他内容保留足够辨识度。
- 侧栏与画布共同占据工作区。打开侧栏时，画布适配剩余宽度，选中节点仍处于可见区域；关闭侧栏后，画布恢复主要阅读空间。
- 侧栏先呈现简述、可分析性和下一步操作；节点事实与代码依据收纳在可展开区域。展开后，每条事实与其来源相邻，便于核对。
- 适合分析的节点突出“分析仓库”；分析说明与仓库链接输入紧邻该操作。暂不适合分析的节点以可读文字说明原因，并保持分析入口的不可用状态清楚可见。

## 比较素材

- 节点分析素材以本项目节点、目标仓库和结论为阅读主轴。对应做法与差异按同一比较点组织，使用户能直接看出两边的做法和证据。
- 本项目事实链接回生成分析时的图版本与节点资料；目标仓库证据指向本次分析使用的提交和具体文件。来源入口贴近其支撑的陈述。
- 未找到对应功能、证据不足和读取失败使用不同标题与状态说明，并显示实际检查范围；结论与证据保持相邻。
- 转发素材延续来源正文、图片和 AI 通用理解的阅读结构；两类素材共用列表、阅读导航与排版层级。

## 排版与内容宽度

- 全部页面共用一套克制的字体层级和控件密度。
- 页面标题、内容标题、正文、标签和辅助信息通过有限层级建立秩序；同一层级在不同任务中保持一致。
- 阅读正文使用适合连续阅读的内容宽度，并在宽窗口中保持居中或与主要内容轴对齐。
- 正文图片遵循内容阅读轴并保持原始比例；来源正文、AI 通用理解和仓库比较通过标题与留白分段。
- 表单控件保持紧凑、清楚且可操作。仓库链接输入与节点分析说明组成一个明确的操作区。

## 窗口适配与滚动

- 宽度充足时保留窄左导航和主要内容轴；窗口变窄时优先收紧外围留白、换行次要信息和重排操作，再考虑简化导航标签。
- 字体和控件保持可读、可操作的下限；空间不足时使用重排和滚动。
- 素材阅读保持一个清楚的主要纵向滚动区域。项目图工作区中，画布承担缩放和平移，节点侧栏独立纵向滚动；导航、图操作和阅读切换按任务需要保持稳定。
- 窗口高度不足时，内容区域滚动，稳定操作区保留；弹出内容与当前主要操作保持可见、可达。

## 共用状态

- 可交互控件至少具有默认、悬停、按下、键盘焦点、禁用和处理中状态，并在跨页面组件中保持一致。
- 键盘焦点使用清晰可见的轮廓；悬停和按下反馈保持克制与布局稳定。
- 禁用状态结合视觉和文案上下文说明原因，保持足够可读性；处理中状态保留控件位置并锁定重复触发。
- 选中、成功、警告和失败状态结合颜色、图标、文字或结构变化表达含义。

## 视觉方向

视觉风格服务于项目图探索和素材阅读：图中关系清楚，操作容易找到，长内容适合持续阅读。

- 背景、文字与强调色建立稳定的对比关系；颜色用于识别主要操作、选中节点和任务状态。
- 标题、正文和辅助信息通过字体、字号、字重与留白形成清楚的层级；阅读内容可以采用适合长文的排版。
- 窄左导航保持稳定，主要空间交给当前任务。项目图以关系结构占据工作区，侧栏以适合连续阅读的宽度呈现节点资料。
- 应用图标以[浅色折带图标](design/branchout-icon-light-master.png)为视觉母版：瓷白色折带向三个方向展开，内侧呈杏橙与淡紫色，背景为浅蓝灰色。应用图标与界面内品牌标志按母版比例导出；项目和仓库使用各自的对象标识。
- 素材列表与阅读流沿用一致的排版层级和对象标识，使用户切换后仍能识别同一条素材。
- 页面与局部组件通过阅读宽度、排版层级和留白组织内容，主要操作保持稳定、易识别的位置。

视觉 token 的精确值在组件规范中定义；字号、控件高度、内容宽度、间距和断点结合真实字体、Electron 窗口与交互验证确定。视觉设计稿表达信息结构、任务分区和整体方向，最终交互以真实内容状态和可用性验证为准。

素材标题列表与阅读流的视觉参考见 [素材列表与阅读流设计图](design/README.md)。
