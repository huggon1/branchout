# Branchout 设计系统

本文定义跨页面共用的信息、文案、操作层级和渐进呈现规则。页面任务与流程以 [UX 规格](ux-spec.md) 为准。

## 信息呈现

- 一个界面只突出当前任务最重要的信息，不让同级标题、说明和操作同时争夺注意力。
- 默认内容帮助用户识别对象、理解状态并采取下一步；补充信息在需要时展开。
- 没有决策价值的信息直接省略，必要提示和异常状态保持可见。
- 标题、标签和按钮使用足够明确的文字，不为每一项附加解释。只有存在歧义、配置前提或重要后果时才补充说明。

## 文案

- 操作文案直接说明动作及对象，避免泛化名称。
- 状态文案描述实际发生的情况，明确区分未执行、未覆盖、无结果、内容不完整、完整性未知和失败。
- 来源内容、AI 通用理解和项目参考使用清楚且一致的名称，不混写成同一种事实。
- 提示信息优先告诉用户当前状态和可采取的下一步，不展示内部实现细节。

## 操作层级

- 每个任务突出清晰的主要操作；次要操作降低视觉权重，低频操作按需收纳。
- 操作放在其作用对象附近：素材操作对应素材，基线操作对应基线，平台配置对应平台状态。
- 相同任务的主要操作保持稳定位置和名称，避免内容变化造成操作漂移。
- 收纳不能牺牲可发现性；用户完成常见任务所需的入口应当直接可见。
- 主要、次要和文字操作使用同一套跨页面层级。主要操作承载当前步骤的完成动作；次要操作用于取消、返回或不改变主要结果的选择；低频文字操作不与主要按钮争夺注意力。
- 长任务中的完成操作保持在稳定且持续可见的位置。滚动内容不推动保存、取消或阅读导航随正文漂移。

## 渐进呈现

- 先显示完成当前步骤所需的信息，再显示解释、配置和细节。
- 展开的内容保持与触发对象相邻，并允许用户回到原来的任务位置。
- 页面层级用于分开不同任务，局部展开用于补充同一对象；不能用不断增加的区块代替任务分层。

## 排版与内容宽度

- 全部页面共用一套克制的字体层级和控件密度，不为单个页面放大标题、按钮或输入区域。
- 页面标题、内容标题、正文、标签和辅助信息通过有限层级建立秩序；同一层级在不同任务中保持一致。
- 阅读正文和长内容编辑区域使用适合连续阅读的内容宽度，并在宽窗口中保持居中或与主要内容轴对齐，不随窗口无限拉宽。
- 正文图片遵循内容阅读轴并保持原始比例；来源正文、AI 通用理解和项目参考通过标题与留白分段，不依靠厚重容器堆叠。
- 表单控件保持紧凑、清楚且可操作。长内容编辑以文档排版承载正文，不呈现为占满页面的空白输入框，也不增加完成任务不需要的工具栏。

## 窗口适配与滚动

- 界面不依赖单一窗口尺寸。宽度充足时保留窄左导航和主要内容轴；窗口变窄时优先收紧外围留白、换行次要信息和重排操作，再考虑简化导航标签。
- 字体和控件保持可读、可操作的下限，不随窗口按比例缩小。空间不足时使用重排和滚动，不压缩成密集小字。
- 每个任务保持一个清楚的主要纵向滚动区域。导航、阅读切换和编辑完成操作按任务需要保持稳定，避免页面与局部容器同时滚动造成位置不确定。
- 窗口高度不足时，内容区域滚动，稳定操作区保留；弹出内容不得遮挡当前主要操作或造成无法恢复的滚动位置。

## 共用状态

- 可交互控件至少具有默认、悬停、按下、键盘焦点、禁用和处理中状态，并在跨页面组件中保持一致。
- 键盘焦点使用清晰可见且不只依赖颜色的轮廓；悬停和按下反馈保持克制，不引起布局跳动。
- 禁用状态同时通过视觉和文案上下文说明不可操作，仍保持足够可读性；处理中状态保留控件位置并避免重复提交。
- 选中、成功、警告和失败状态不能只靠颜色区分，配合图标、文字或结构变化表达含义。

## 视觉方向

界面采用清爽、克制的工具感，帮助用户快速识别信息与操作，不用装饰性视觉抢占内容注意力。

- 整体使用冷调浅色背景，通过轻微明度差区分页面、导航和内容区域。
- 文字使用清晰的无衬线字体，标题、正文和辅助信息依靠字号、字重与留白建立层级。
- 主要任务入口使用窄左导航组织，导航保持稳定、低干扰，并为内容区域保留主要空间。
- Branchout 应用图标与左上品牌标志统一使用青绿色分支叶片图形，并与 Branchout 字标组合时保持同一比例与间距。品牌标志只识别应用，不用于表示当前项目或绑定仓库；项目与仓库继续使用各自的对象图标和名称。
- 导航中的留白保持安静，不放置装饰性口号或填充性说明。
- 青绿色作为克制的强调色，用于主要操作、选中状态和必要的进度或反馈，不作为大面积装饰底色。
- 素材标题列表与阅读流使用同一套冷调背景、无衬线排版和青绿色强调，切换任务时保持连续的产品气质。
- 界面不使用暖纸色背景或衬线字体营造阅读刊物感。
- 页面与局部组件统一精修，克制使用字号和控件高度，通过合理的阅读宽度、清楚的排版层级与留白组织内容，并为主要操作保留稳定、易识别的位置。
- 长内容编辑区域首先服务于阅读和修改，不因可用空间增加而无节制拉伸，也不把一个空白输入区域作为页面的主要视觉结构。

字体、颜色、间距、圆角、阴影和其他视觉 token 的精确值在组件规范中定义，但必须保持上述视觉方向，本文不预先固定具体像素值。信息层级、操作归属、稳定位置、状态集合、重排顺序和滚动边界可以在设计文档中精确定义；具体字号、控件高度、内容宽度、间距和断点需要结合真实字体、Electron 窗口和交互实现验证后再进入组件规范。视觉设计稿用于表达信息结构、任务分区和整体方向，属于后续统一精修的输入；其中的窗口比例、控件尺寸、字体大小、编辑区域形态和局部精细度不作为最终视觉验收标准，也不替代交互契约、真实内容状态或可用性验证。界面方案不使用字符或 ASCII 拼接界面图。
