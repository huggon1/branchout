# Feedloom 项目规划

## 1. 定位与交付边界

Feedloom 为个人产品构建者提供基于 GitHub 仓库的探索与阅读工作空间：项目回顾建立上下文，内置角度引导外部探索，素材库承接发现，人工选材生成 Feed。转发解析保持独立。

产品行为及五类角度以 [MVP PRD](mvp-prd.md) 为准，模块职责和数据关系以[技术架构](technical-architecture.md)为准。本文件定义实现顺序、复用范围、验收门槛和接入与兼容选择；[根 README](../README.md)描述实际可运行状态。规划不是新功能已交付的证明。

macOS 桌面首发，预留 Windows；Electron、React、TypeScript、Pi 和 SQLite 继续作为技术基础。用户在本机保存业务数据，不建设产品账号、云端业务服务或跨设备同步。模型沿用个人试用的 Codex 与 Luna 路径并保留 API Key，不自动更换模型或计费方式。

所有仓库分析与探索由用户手动发起。多仓库分别分析，多选仅产生独立组合，不发展为多仓库联合研究或工作流编辑器。外部内容质量以实际阅读价值衡量，不以平台数、素材数或章节齐全为成功标准。

| [持久化](../src/core/store.ts)                                                                              | 复用 SQLite、事务和 Feed 快照；增加版本引用、增量边界与多对多发现关系，迁移现有 v2 数据                   |

| [GitHub 适配器](../src/adapters/github.mjs)、[社交适配器](../src/adapters/social.mjs)                       | 复用外部搜索；独立增加 GitHub 只读 Token、绑定仓库文件与变更读取                                          |

| [主进程](../src/core/main.ts)、[预加载通信](../src/core/preload.ts)                                         | 分离仓库分析、探索批次和 Feed 命令；更新权限和外部链接校验，移除新流程调度入口                            |
| [桌面界面](../src/ui/main.tsx)、[任务表单](../src/ui/TaskEditor.tsx)、[探索过程](../src/ui/RunResearch.tsx) | 复用阅读、选材与执行进度；替换自由任务配置，增加项目回顾、组合启动与依据版本展示                          |
| [桌面测试](../tests/e2e/desktop.mjs)、[真实验证](../scripts/verify-live.mjs)                                | 更新场景以覆盖仓库分析、探索关系与分章 Feed；保留转发回归                                                 |

仓库授权读取与外部 GitHub 搜索是不同能力，分别验证。受控测试证明语言改词、补读及状态机制；产品场景相关性与实际来源覆盖仍通过真实样例验收，本版不接通用网页来源。

- 支持 Codex 订阅模型选择和自定义 OpenAI 兼容 API，多连接保存、单个启用，并通过统一 Pi Agent 层测试与调用；不自动切换模型或计费方式。用户按需完成模型及平台登录；应用携带所需运行依赖，普通用户无需安装开发环境或操作 CLI。
- 关闭窗口后可驻留完成手动工作或接收机器人消息；退出应用或电脑关机后停止。
- 保留可获取的正文、元数据、来源和必要媒体缓存，不默认下载完整音视频。
- 应用更新时支持必要的数据迁移；首版不提供手动备份、导出和恢复功能。
- 首版先交付 huggon1 本机可安装、可真实运行的 macOS 应用；对外分发前再完成签名、公证，暂不进入应用商店；提示新版本后由用户下载安装，自动更新后续再考虑。

## 3. 实现阶段与完成门槛

### 阶段 1：契约、数据升级与接入验证

先落实第 5 节的接入和兼容选择，再扩展运行时 schema、导出契约与 fixtures。数据对象分离素材正文和发现关系，分析与探索均以不可变输入快照执行，Feed 固定完整生成依据。

接入验证只使用用户授权的环境；仓库内测试采用虚构样例。验证 GitHub 公开/私有读取、固定版本文件、变化边界与分页完整度；验证平台正文读取、时间证据、错误分类与打包依赖。参考 Last 30 Days 的查询规划和补搜方式，通过适配器接入可验证能力，不把整个 Skill 的输出格式或权限约定移植成产品规则。

完成门槛：

- 成功、空结果、依据不足、权限失败、限流、部分读取和中断契约独立可测；
- 升级事务失败可回滚，旧数据仍可读，历史来源不能自动伪造为仓库发现；
- 私有仓库数据不进入公开搜索词、日志或测试快照；
- 明确 GitHub Token 和社交平台的用户配置入口、外部账号条件及能力限制；无法完成接入的能力不标可用。

### 阶段 2：项目回顾真实闭环

实现绑定、手动分析、固定仓库输入读取、产品主理解和近期变化产出。先建立不可变分析记录，再更新当前成功版本指针与增量边界。页面独立展示当前理解及变化历史，不加入理解编辑、确认或学习管理功能。

完成门槛：公开和已授权私有仓库分别可分析；首次与增量边界准确，噪声过滤有证据；失败不推进边界，不覆盖旧成功结果；文件与 PR/commit 引用可核验；信息不足和无变化不凑内容。

### 阶段 3：探索模板、组合执行与素材关系

内置 PRD 的五类模板及启动提示词，不开放用户编辑。启动时按仓库与角度的笛卡尔积创建批次和组合，固定理解版本、模板版本、时间范围和启用平台。复用多轮循环，扩展按社区选择语言、候选正文读取、缺口反馈与停止判定。

每个组合可在自己的已选平台间补充证据；组合之间保持独立。单组合预算之外提供批次总量和并发约束，避免仓库与角度数量放大后失去限制。数值按实际运行校准，不机械复制旧单任务预算到每项。

完成门槛：

- 2 个仓库 × 3 个角度形成 6 个独立输入与状态，部分失败可继续与重试；
- 探索仅使用已有理解，界面准确显示版本，过程中新增理解不会改变输入；
- 中英文表达、名称歧义、空首轮后换词、正文不足后补读都有受控样例；
- 相关性摘录及近期活动证据可核验，平台失败与无结果分开；
- 多次发现同一来源保留独立理由，重试幂等，不凑素材。

### 阶段 4：选材、分章 Feed 与页面整合

按 PRD 更新素材筛选、重叠标记、主章节归属、顺序与来源快照核对。逐条生成时传入正文与对应发现理由，增加依据不足状态；组装成品时省略无成功条目的章节。保留生成配置、逐项重试、单条替换和重新生成整份的原有边界。

完成门槛：跨仓库与日期选材不丢失选择，同来源只生成一次；章节可调整且生成前可见；部分失败成功项可读可复制，全部失败不伪装成成品；更新理解、模板或素材不会改变历史 Feed；转发解析、阅读和删除回归通过。

### 阶段 5：历史兼容、质量与桌面交付

完成旧任务与素材的兼容呈现、定时执行退役和各入口导航调整。保留历史证据，清理运行时自动调度、错过计划与补跑触发路径；不得只隐藏按钮仍在后台执行。历史任务只读保留，无探索关系的旧素材默认进入“历史素材”章节。

运行仓库检查、桌面 E2E 和真实接入验证。桌面覆盖关闭窗口驻留、退出、中断识别、取消、重试及数据升级；真实内容只保存在本机测试工作空间。安装包验证随包依赖，无开发环境验收、签名和公证仍是对外分发门槛。

质量评审固定仓库理解、模板、平台与时间范围，分别检查五类角度：关联是否具体、来源是否可靠、摘要是否忠实，以及 huggon1 是否愿意打开原文或深入理解变更。记录无产出案例与平台限制；搜索次数和模型自评不能证明用户价值。转发继续覆盖 Telegram／飞书本人私聊、配置与绑定、消息去重恢复，以及完整 README 图文阅读；真实机器人权限由 huggon1 在独立测试版中验收。

完成门槛：PRD 核心场景通过，有真实中英文探索和私有仓库运行证据；不把替身测试称为真实效果验收；README 根据交付实现更新，页面说明和架构不存在过期规则。

## 4. 验证与文档责任

- 每个契约变更同时更新 fixtures、契约测试和适配器；状态恢复、边界推进、关系幂等、Feed 快照和迁移使用确定性测试。
- 页面验证使用 [PRD](mvp-prd.md) 的桌面尺寸和异常场景；新项目回顾和探索页面不能以旧静态图代替交互验收。
- 实现提交前运行 `npm run check`；受影响桌面流程运行 `npm run test:desktop`，交付运行 `npm run package:app`，真实验证使用更新后的对应脚本。只改文档至少运行 `npm run check:docs` 与 `git diff --check`。
- README 记录实际交付状态；PRD 负责行为，技术架构负责机制，本文负责阶段与接入待定项；不另建实施日志或重复设计文档。

## 5. 已确定的接入与兼容选择

- GitHub 使用应用内配置的只读 Token，默认分支及相关已合并 PR 构成分析范围。公开仓库可无 Token 读取，私有仓库需要用户在 GitHub 授予访问权限。
- 本版不支持通用网页搜索，仅使用 GitHub、小红书和 X；不引入 Brave Key 或 SearXNG 配置。
- 同日覆盖、跨日保存采集记录，列表按来源去重；历史 Feed 的实际快照不迁移为当前素材引用。
- 旧任务停用调度、只读保留，旧素材仍可选，缺少探索角度时归入历史素材。
- 每批最多 10 项、逐项运行；每组合与每批的执行上限以 PRD 为准。这些是保护性限制，搜索质量和耗时体验仍需实际使用校准。

## 6. 真实验收需要的用户配置

私有仓库验收需要用户在应用内配置有权限的 GitHub Token。小红书、X 的真实探索需相应平台登录；不将已有个人浏览器登录态自动复制到测试环境。模型需有效 Codex 登录或用户配置的 API Key。不具备这些条件时运行受控测试和公开仓库验证，并明确保留未验证项。

开源许可证、正式分发签名和公证仍待后续处理，不影响本机试用。
