# Feedloom 项目规划

## 1. 定位与权威文档

Feedloom 面向个人阅读和可直接复制的知识分享、产品发现。独立管理转发内容，通过收集任务持续获得素材，再人工选材并按提示词生成 Feed。

具体术语、页面职责、使用规则和验收场景以 [MVP PRD](mvp-prd.md) 为准。本文件负责产品方向、交付阶段和工程边界；当前仓库状态以 [README](../README.md) 为准。旧版 Pitch 已移除，历史演示不作为 MVP 的实现依据。

仓库名称为 Feedloom，GitHub 可见性为 Public，开源许可证尚待确认。

## 2. 产品方向

- 个人使用、桌面优先，验证收集、选材、阅读与复制分享的完整体验。
- 转发解析与持续收集独立。转发解析支持 GitHub 和小红书，以粘贴链接为入口。
- 收集使用任务配置，以 last30days 为能力基础；展示已接入平台及可用状态，不把工具声明视为验证结果。
- 结果是独立来源条目。规则筛选入库，模型只生成摘要；不引入模型筛选或跨来源语义合并。
- Feed 由用户选材触发，提示词属于生成配置，不提取或绑定博主风格。
- 生成内容必须能追溯原始来源和收集记录。

### 桌面交付边界

最终交付可分发的个人桌面应用，macOS 首发，预留 Windows；每个用户在本机独立保存数据，不建设产品账号或跨设备同步。

- 用户提供模型 API Key，按需主动完成平台登录；应用携带所需运行依赖，普通用户无需安装开发环境或操作 CLI。
- 关闭窗口后可驻留运行；退出应用或电脑关机后暂停，启动后提示补跑错过的任务。
- 保留可获取的正文、元数据、来源和必要媒体缓存，不默认下载完整音视频。
- 应用更新时支持必要的数据迁移；首版不提供手动备份、导出和恢复功能。
- macOS 通过经过签名、公证的安装包直接分发，暂不进入应用商店；提示新版本后由用户下载安装，自动更新后续再考虑。

选型、模块职责与运行机制以[技术架构](technical-architecture.md)为准；两条流程和具体功能范围仍以 PRD 为准。

## 3. 交付阶段

### M0：仓库基础

建立公共仓库、项目说明、开发约束、忽略规则和文档政策。仓库不包含凭据或真实私人内容。

### M1：产品 Pitch

该阶段用于通过确定性假数据与讲解页面探索产品体验。旧版 Demo 已从当前代码中移除，仅保留 Git 历史；后续实现遵循 MVP PRD 和页面设计。

### M2：MVP PRD 与页面设计

先讨论确认使用设计，形成不包含技术细节的 PRD。随后讨论视觉注意事项，通过生图确认页面，将图链接回 PRD 并检查一致性。

完成标准：

- 术语、页面职责、主要操作、更新规则和异常体验明确；
- 页面设计与 PRD 一致，关键流程可据此理解和评审；
- 规划与已确认方向一致，README 不把规划写成已实现功能；
- huggon1 确认 PRD 质量后提交并合并 PR。

### M3：最小协作契约与能力盘点

以 PRD 为依据确定模块交换的数据，使用版本化 JSON Schema、代表性 fixtures 和契约测试。覆盖转发内容、收集任务、收集记录、收集条目、生成配置、生成结果及来源引用，不提前建设复杂服务治理或通用工作流引擎。

盘点已有仓库、工具、Skills 和本地服务的维护状态、调用入口、输入输出、鉴权要求、回放测试能力和适配缺口。验证 last30days 的来源可用性、时间窗口、指标和筛选边界，避免引入不符合 PRD 的重排与聚合行为。

完成标准：契约独立可测，包含成功与异常状态，外部数据结构不泄漏到核心领域；明确可用平台与条件后再承诺界面能力。

### M4：真实 MVP 链路

复用已验证能力，按 PRD 跑通两条独立流程。真实模块接入前先验证桌面运行时、Pi 集成和依赖打包，具体验证见[技术架构](technical-architecture.md)。

完成标准：

- GitHub 和小红书链接形成可阅读、可追溯的转发记录，失败和部分解析如实显示；
- 至少一个任务完成真实收集，按规则形成条目列表；
- 用户能跨任务、跨日期选材，使用提示词逐条生成并保存 Feed；
- 复制整份或单条保留来源，覆盖更新不改变已有 Feed；
- 部分失败保留成功结果且可重试；
- 按 PRD 核心验收场景验证体验；
- 桌面交付覆盖驻留、退出、中断识别、取消和数据迁移；正式分发前完成签名、公证及无开发环境安装验证。

### M5：分模块优化

链路成立后，再提升解析成功率、收集相关性与稳定性、摘要忠实度、Feed 可读性、响应速度和异常恢复。使用真实样例和人工对比验证，不以平台数量为主要成功标准。新增范围先由 huggon1 确认。

## 4. 工程与数据边界

- 外部能力通过适配器或防腐层接入，不直接复制外部仓库实现；可替换适配器而不改变其他模块。
- 契约变化在同一 PR 中同步相关 fixtures、测试和适配器。
- 登录态、密钥、私有内容和真实用户数据不得进入仓库、日志或测试快照；私有运行数据与公共代码分离。
- 默认演示样例使用虚构或明确可公开使用的内容，模拟解析、收集和生成明确标记。
- 真实失败不伪装成空结果或完整内容，生成结论保留证据入口。
