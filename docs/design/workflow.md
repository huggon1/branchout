# 持续界面设计流程

## 每次改界面前

先读 [PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md) 和本目录[页面职责](README.md)。产品行为以 [MVP PRD](../mvp-prd.md) 为准；不从风格图推导功能。阅读与判断、探索与控制、选材与产出没有全产品的固定主次，应按当前页面的任务确定层次。

普通迭代直接复用设计变量和组件规则。新页面不是新品牌，不再重新选择配色、字体和图标系统。只有明确更换视觉方向时才做新的风格选择。

## 更换视觉方向

1. 审视真实内容、现有界面和任务，先区分功能问题与视觉问题。
2. 给出少量可比较的风格板，展示色彩、字体关系、图标线条、控件和状态；中文说明。不要用整页效果图意外锁定布局。
3. 用户选择视觉语言后，再按真实内容实现页面。风格板内生成的文案、数字和状态不是产品事实。
4. 使用真正运行的 Electron 页面验证，合格后把实际采用的规则写回 DESIGN.md。

## 实现与复用

- [tokens.css](../../src/ui/tokens.css) 是颜色、字体、间距、圆角、反馈时长的运行时来源；避免在页面上另造一套色值。
- [style.css](../../src/ui/style.css) 承载组件与布局。优先修改既有规则，避免不断追加相互覆盖的补丁。
- [Icons.tsx](../../src/ui/Icons.tsx) 统一导航与动作图标。品牌标记独立，不复用素材库图标做 Logo。
- 新增状态先明确含义，再选择语义色；文字必须能独立说明状态。原始内容、AI 摘要与发现理由不能混成一段。
- 模型、登录和真实平台的能力不能用纯视觉示例冒充。

## 验收与收尾

桌面尺寸为 1100×720、1280×800、1440×940。使用隔离数据库和明确标注的虚构数据，覆盖长标题、多重来源、空内容、执行中、部分成功及失败。

运行 `npm run check` 和 `npm run test:desktop`。截图前等待字体及页面状态稳定；检查内容区和操作区，不只检查页面有没有横向滚动。尤其要看生成区标题是否被章节控件挤压、错误信息是否遮住恢复入口。

做一轮独立视觉审阅，集中修正问题后复核。同步更新 DESIGN.md、`.impeccable/design.json` 和必要的组件规则；不将某一张页面的布局提升为全产品的硬约束。Impeccable 是可用辅助工具，未安装的 agent 仍可按本文件完成设计流程。

用户确认实际预览满意后，才提交并合并本轮重构；开发过程按已完成部分分别提交，不把全部工作挤成一个提交。

## 组件验收不能被配色替代

更改 token 或字体不代表完成界面重构。必须检查输入框、选择菜单、勾选行、折叠区及按钮的结构、命中范围与完整状态，并在真实桌面应用中留存证据：

- 输入框：默认、焦点、禁用和错误；标签及提示保持可读。
- 选择菜单：闭合与实际展开，键盘选择；菜单不得只验收闭合边框。
- 复选框：未选、已选、半选、禁用与空格键操作，选择行可点击。
- 折叠区：整行命中、打开/关闭与键盘操作；标题、箭头、正文层次一致。
- 按钮：主操作、普通操作、安静操作及图标按钮区分；检验禁用和焦点。
