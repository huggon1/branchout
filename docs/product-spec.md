# Branchout 产品规格

Branchout 围绕正在构建的项目，帮助用户发现、收集并理解有用信息，使探索从项目语境出发，并保留可核验的来源。

## 产品范围

Branchout 绑定用户本机的 Git 仓库，读取当前代码和文档，以此建立项目语境。第一版不要求运行项目或观察实际界面，也不分析 Git 历史、开发时间线或独立的通用项目概述。

产品围绕三件事展开：

1. 建立并维护项目的产品基线和 UI/UX 基线。
2. 基于对应基线，分别进行产品探索和 UI/UX 探索。
3. 接收用户转发的链接，提供与项目无关的通用理解与阅读体验。

产品提供逐条素材的 AI 通用理解，不包含内容生成功能。

## 项目与基线

每个项目独立保存两份可编辑的基线理解报告：产品基线用于理解产品，UI/UX 基线用于理解 UI/UX。

两份报告都支持一键生成，用户也可以编辑生成结果或完全自行填写。用户首次直接发起某一方向的探索时，如果缺少对应基线，系统自动生成后继续探索，不要求用户先补充目标、“正在考虑什么”或确认报告。已有基线默认可以复用，用户也可以选择重新生成。

重新生成已有基线时，旧基线保持不变，新结果先作为预览呈现。只有用户明确选择替换，新结果才成为当前基线；用户取消则继续保留旧基线。用户在发起探索时选择重新生成，也必须完成相同的预览与替换确认；选择取消后返回原探索表单，不自动继续探索。确认完成前，探索不能使用新结果继续执行。

## 探索

探索只有两个方向：产品探索和 UI/UX 探索。每次探索由用户手动发起，不提供定时运行或独立的“深度分析”任务。关闭应用窗口后，正在进行的探索继续在后台运行。

探索运行期间，用户提交的新转发可以开始解析，无需等待整轮探索结束；具体同时执行数量由实现控制。

每个方向对应一套应用预设方案。方案决定使用哪些平台以及探索方式；用户选择方向，不逐个平台勾选。界面需要让用户看懂方案用途、涉及的平台，以及各平台当前是否可用或需要配置。

执行时，Agent 使用对应项目基线，在方案包含的平台上进行多轮搜索、筛选，并逐条读取和摘录候选素材。每条入选素材记录：

- 为什么与当前项目相关；
- 哪些具体内容值得参考。

探索不生成跨素材综合报告。搜索侧重、查询词和提示词属于实现优化，不固化为产品规则。

平台未配置或暂不可用时，本次探索跳过该来源，继续使用其他可用平台。结果必须明确说明该来源未被覆盖，不能把“没有搜索”表述成“没有结果”。

探索产生的素材自动继承本次探索的项目、方向和分析上下文，用户无需再次手动关联。产品不提供按探索轮次回看的专门入口。

## 平台范围与配置

第一批内容平台为 X、小红书和 GitHub。产品探索与 UI/UX 探索的预设方案只能在这个集合内选择平台；两个方向不要求覆盖全部三个平台，具体映射和搜索方式由各自方案根据效果持续优化。Agent Reach 可以作为能力设计参考，但其文档能力不能被描述为 Branchout 已实测能力。

普通网页、Reddit、V2EX、Facebook、LinkedIn、RSS、Product Hunt 和 Hacker News 不属于第一批内容平台承诺。Instagram 和雪球明确不在范围内，第一版不做视频解析或音频转录。

平台按需配置，不要求用户首次使用时完成全部登录。平台配置由探索与转发共用；同一平台的搜索与详情读取可能有不同登录要求，能力状态需要分别如实呈现。

## 模型连接

第一版只保存一个当前模型连接，不提供连接列表、多个连接的切换管理或按任务选择模型。基线生成、产品探索、UI/UX 探索和转发内容理解共用这个当前连接。

用户从两种连接方式中选择一种：

- **通用 API**：配置 API Key、服务地址、接口类型和模型标识。第一版只支持 OpenAI Responses 与 OpenAI Chat Completions 两种明确接口，不把任意自定义协议或仅声称“OpenAI 兼容”的服务视为已支持。
- **Codex 订阅账号**：通过 Codex 登录流程登录 ChatGPT 账号，再从该账号和当前 Codex 客户端可用的模型中选择一个模型。

当前连接方式改变时，设置界面只展示所选方式的配置，不同时堆叠两套表单。模型连接是 Agent 执行的全局配置，不改变各类任务的业务输入、平台范围或素材保存规则。

保存新的当前连接只影响之后创建的任务。已经运行的任务继续使用启动时取得的连接配置，不在执行中热切换或自动重启。

## 转发、获取与内容理解

转发通过三种入口接收链接：应用内添加链接、飞书和 Telegram。三个入口进入同一套转发处理流程，获取链接内容并给出通用理解。飞书和 Telegram 分别配置、互不依赖；其中一个渠道未配置或不可用时，不影响另一个渠道和应用内添加链接。

转发不要求选择项目，也不推断用户的项目意图或转发意图。

转发与探索共用平台配置、内容获取与解析能力，以及平台通用理解能力。每次转发按单条素材完成获取、通用理解并保存为转发素材记录。内容理解分为两个清晰层次：

- 平台通用理解：围绕来源本身生成适合其内容形态的可读理解。
- 项目参考：仅探索素材拥有，说明内容对当前项目的参考点。

来源内容与 AI 通用理解必须分开保存和呈现。项目参考可以在阅读页中作为独立章节出现，不要求独立数据库。

同一链接分别经转发和探索进入 Branchout 时，保留两条独立素材记录，不自动合并。

## 素材与阅读

所有素材进入统一列表，至少可以按平台、类别和时间识别；类别为产品探索、UI/UX 探索或转发。探索素材另外标明所属仓库。

每条素材尽量保存并呈现完整正文和图片，同时提供 AI 通用理解与原链接；探索素材另附项目参考信息。内容获取不完整或无法判断完整性时，必须如实说明，AI 不得补写未获取的原文。

## 逻辑职责

系统由八类逻辑职责协作完成上述体验；它们不等于独立包、进程或部署单元。职责关系见 [架构总览](architecture-overview.md)。

## 实现裁量

常规的失败、取消与重试行为由实现者按一致、可恢复、状态透明的原则合理设计，不需要逐项等待产品确认。
