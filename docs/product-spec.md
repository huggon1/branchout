# Branchout 产品规格

Branchout 围绕正在构建的项目，帮助用户从项目图的具体节点出发，发现其他开源项目的相关做法，形成有依据、可回看的比较素材。用户主动转发的内容也进入素材库，供独立阅读和理解。

## 产品范围

Branchout 绑定用户本机的 Git 仓库。项目管理负责添加、选择和删除项目；UI/UX 与功能模块是两个独立入口，用户在各入口内选择项目并使用对应的项目图。

首版围绕三件事展开：

1. 从本机项目当前代码生成并维护 UI/UX 项目图与功能模块项目图。
2. 从可分析节点出发，由用户指定公开 GitHub 仓库，生成一次有依据的做法比较并保存为素材。
3. 接收用户转发的链接，提供与项目无关的通用理解与阅读体验。

追踪新近信息以后作为独立功能设计；节点分析可以长期回看。

## 项目图

每个项目在 UI/UX 和功能模块方向各维护一张当前项目图。用户首次进入某方向并选择项目时，系统从该项目当前本机文件初始化对应的图；尚未提交的文件修改也属于本次生成依据。UI/UX 图表达用户任务中的交互步骤与转移，功能模块图以产品能力为节点、呈现能力之间的关系。两张图分别生成和使用，项目代码变化后由用户手动重新生成。

项目图借助 Archify 呈现为可交互的动态视图，支持节点聚焦、缩放和路径查看。用户可以选择节点查看详情。

每次成功生成都形成独立的图版本，并保存生成时的项目状态与节点资料。重新生成产生新的当前版本；旧分析仍归属原图节点。代码变化后，用户仍可在旧图上发起分析；界面须清楚标明该图所依据的项目状态。旧图版本及其节点资料可从关联素材回看。

删除项目后，项目从可选列表移除；已经保存的素材及其回看所需的图版本和节点资料继续保留。

## 节点资料与可分析性

图生成后，系统对每个节点补充分析，形成与该图版本一起保存的节点资料。节点资料包含简述、基于本机代码得到的具体事实和来源依据，以及是否适合发起仓库分析的判断。适合分析的节点还包含固定的分析说明，告知用户接下来会比较什么。

目标明确、范围足以定位对应做法、且本项目有足够代码依据的节点开放仓库分析。其他节点仍可查看详情，分析入口显示不可用的原因。节点资料和图由静态代码分析生成。

后续节点分析以该图版本冻结的节点资料为本项目依据。资料不足以支持可靠比较时，系统说明不足并建议重新生成图。

## 基于节点的仓库分析

用户在项目图中选择一个可分析节点，通过节点详情手动输入一个公开 GitHub 仓库首页链接，发起一次仓库分析。每次分析对应一个节点和一个目标仓库；同一仓库可以在以后再次分析，每次结果独立保存。

系统依据冻结的节点资料，在目标仓库的文档和静态代码中寻找对应功能或交互做法，比较本项目节点与目标仓库的实现，并给出具体差异及可核验的依据。分析固定目标仓库本次读取所依据的提交版本，结论对应实际检查范围。

每次完成分析产生一条素材。找不到对应功能时，仍保存本次检查范围和结论，并区分“有依据确认没有对应功能”“已检查但证据不足”和“读取失败”。分析任务在窗口关闭期间继续运行；重新打开后可以查看任务状态与已保存结果。

## 模型连接

第一版使用一个当前模型连接，供项目图与节点资料生成、仓库分析和转发内容理解共用。

用户从两种连接方式中选择一种：

- **通用 API**：配置 API Key、服务地址、接口类型和模型标识；接口类型为 OpenAI Responses 或 OpenAI Chat Completions。
- **Codex 订阅账号**：通过 Codex 登录流程登录 ChatGPT 账号，再从该账号和当前 Codex 客户端可用的模型中选择一个模型。

设置界面根据当前选择的连接方式展示对应配置。

保存的新连接供后续任务使用；已经运行的任务沿用启动时的连接配置。

## 转发、获取与内容理解

转发通过三种入口接收链接：应用内添加链接、飞书和 Telegram。三个入口进入同一套转发处理流程，获取链接内容并给出通用理解。飞书和 Telegram 分别配置，应用内添加链接独立可用。

转发独立于项目。每次转发按单条素材完成来源获取、通用理解和保存；来源内容与 AI 通用理解分开保存和呈现。内容获取不完整或无法可靠判断完整性时，明确标出已知缺失或完整性未知的原因，通用理解基于已获取的内容。

转发可读取的首批内容平台为 X、小红书和 GitHub，这些平台在转发中按需配置。同一链接或仓库经不同任务进入 Branchout 时，每次形成独立素材记录。

## 素材与阅读

转发素材和节点分析素材进入同一个素材库。列表至少能按类别、来源和收集时间识别；节点分析素材还标明所属项目、方向与节点。用户继续通过素材列表和单条阅读界面查看内容。

转发素材以获取到的来源正文和图片为阅读主体，并提供独立的 AI 通用理解与原链接。节点分析素材以本项目节点、目标仓库对应做法、具体差异及依据为阅读主体，仓库文档和代码作为来源依据。找不到对应功能的素材也清楚呈现其结论、检查范围与不确定性。

每条节点分析素材保留生成时的图版本、节点资料，以及目标仓库的提交与文件依据。旧素材的来源始终指向当时的图节点和目标仓库版本；项目图重新生成或本机项目绑定删除后，素材仍可阅读并回看必要的来源信息。
