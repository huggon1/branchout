# Branchout UX 规格

产品范围和业务规则以 [产品规格](product-spec.md) 为准。本文规定任务界面的目的、信息层级、触发行为与主要流程；跨界面共用的信息、文案和操作规则见 [设计系统](design-system.md)。任务界面可以由页面、局部区域或临时界面承载，不与固定的页面数量绑定。主要任务入口由窄左导航组织，包括素材、探索、项目和设置。

## 素材列表与阅读流

应用打开后进入统一素材列表。列表帮助用户浏览已有素材、识别来源与上下文，并选择阅读起点。

每条素材以可识别名称为主要内容：优先显示来源标题；来源标题未知时，使用明确来自来源身份或链接的名称，不生成貌似原始标题的文字。同时轻量显示平台、类别和时间；探索素材另外显示所属仓库。列表不展示正文、AI 通用理解或项目基线。列表顶部提供搜索、筛选和“开始阅读”，这些操作始终对应当前素材列表及筛选结果。

列表提供“开始阅读”，从当前筛选结果的第一条素材进入阅读流。用户也可以点击任意素材名称，从该条素材进入同一个阅读流。项目、探索和平台配置的入口与素材阅读操作分开，保持可发现，但不把这些任务的完整内容铺在素材列表中。

素材页提供次级、轻量的“添加链接”入口，用户可以在应用内粘贴链接并开始转发处理。该入口不加入主导航，也不改变标题列表和阅读流的主要任务。

阅读流一次聚焦一条素材。顶部稳定提供“返回列表”“上一条”和“下一条”，并显示当前素材在本次阅读序列中的位置。阅读流就是素材的完整阅读体验，不另设重复的素材详情界面。

来源身份、内容获取完整性和原链接位于阅读内容起始区域，打开原链接的操作与来源信息相邻。已获取的正文与图片构成主要阅读区域，其后呈现独立的 AI 通用理解；探索素材再呈现独立的项目参考。转发素材不显示推断出的项目关联或转发意图。这些内容可以随正文自然延伸，不要求全部进入首屏。

内容获取不完整或无法可靠判断完整性时，对应范围或原因与正文一起明确呈现，不用 AI 补写原文。正文区域的滚动只用于阅读当前素材，滚动到底不会自动切换素材。用户通过顶部“上一条”和“下一条”在当前列表中连续阅读。选择“返回列表”退出阅读流后，界面恢复进入阅读前的列表及原位置，使用户继续当前浏览任务。

## 项目与基线

项目与基线界面帮助用户选择本机 Git 项目，并查看和维护该项目独立保存的产品基线与 UI/UX 基线。

界面显示当前项目、两类基线是否存在，以及当前查看的基线内容。没有报告时，对应基线提供“生成”和“自行填写”；已有报告时，只提供“编辑”和“重新生成”。操作位于对应基线范围内并保持直接可发现，避免用户误把一种基线的操作作用于另一种基线。

进入编辑后，界面清晰呈现可编辑的基线内容，并提供“保存”和“取消”等完成当前编辑所需的操作。编辑区域保持合适的阅读宽度、排版层级和留白，以内容结构和稳定操作区组织编辑任务；不要求复杂富文本能力。

已有基线可以直接用于探索，用户也可以在发起探索前选择重新生成。重新生成后，界面将新结果作为预览与当前基线清楚区分，并提供“替换”和“取消”；其数据保护规则以 [产品规格](product-spec.md#项目与基线) 为准。从探索入口进入预览后选择“取消”，界面保留旧基线并返回原探索表单，不自动启动探索。项目切换和基线维护只呈现当前操作所需的信息，不展示 Git 历史、开发时间线、项目运行结果或独立通用项目概述。

## 发起探索

发起探索界面帮助用户为一个项目选择产品探索或 UI/UX 探索，并在了解方案覆盖后启动任务。

界面显示当前项目、两个探索方向、各方向用途、方案涉及的平台，以及各平台是否可用或需要配置。平台范围由方案决定，用户不逐个平台勾选。需要配置的平台在其能力状态附近提供配置入口；补充方案信息由用户查看对应方向时出现。

启动操作与当前选中的项目和探索方向保持相邻，使用户能够确认将要执行的任务。对应基线不存在时，系统先自动生成再继续探索；已有基线直接复用，用户也可以选择重新生成。选择重新生成时，界面先进入同一套预览与替换确认，确认完成前不进入使用新基线的探索进度。界面不展示内部提示词、模型调用参数或独立深度分析选项。

## 设置与平台配置

设置界面将“模型连接”“转发渠道”和“内容平台”分开呈现。模型连接决定所有 Agent 任务使用的模型；转发渠道负责接收链接，包括飞书和 Telegram；内容平台负责搜索或读取链接指向的内容。三者名称、状态和配置区域保持区分。

### 模型连接

模型连接区域只显示一个当前连接。顶部提供“通用 API”和“Codex 订阅账号”两个互斥选项；切换选项时，只展开对应表单，不在同一页面堆叠两套字段，也不展示连接列表、连接名称、启用开关或删除操作。

选择“通用 API”时，表单包含：

- API Key：密码输入，不在保存后的界面中回显；已有凭据只显示“已配置”状态。
- 服务地址：模型服务的基础地址。
- 接口类型：只提供 OpenAI Responses 和 OpenAI Chat Completions；不提供“自动兼容”或任意协议选项。
- 模型标识：服务实际接收的模型 ID，由用户填写。

选择“Codex 订阅账号”时，未登录状态提供“登录 ChatGPT”操作；登录完成后显示不含令牌的账号状态、模型选择和“刷新模型”操作。模型选择来自当前登录账号与 Codex 客户端查询到的可用列表；刷新失败时保留当前已选模型并明确显示失败，不能用 Pi 内置模型目录假装刷新成功。

保存成功后，该连接成为基线生成、探索和转发内容理解共用的当前连接。界面只展示连接方式、模型和可用状态等非敏感摘要，不显示 API Key、访问令牌、刷新令牌或内部认证文件位置。

保存新连接时，界面明确提示“新连接将用于后续任务”。正在运行的任务继续使用启动时的连接，不出现中途切换或自动重启提示。

飞书和 Telegram 分别显示配置状态，并各自提供配置或重新连接操作；配置其中一个渠道不要求先配置另一个渠道。应用内“添加链接”位于素材页，不作为需要配置的转发渠道展示。

内容平台列表只展示第一批的 X、小红书和 GitHub，并为每个平台分别显示搜索能力状态、详情读取状态和配置状态。用户展开需要处理的平台后，界面提供该平台的配置内容和必要说明；配置或重新连接操作位于对应平台状态附近。平台按需展开和配置，不要求用户一次完成全部平台设置，也不把未纳入第一批的平台展示为可配置能力。

## 运行状态

运行状态界面帮助用户判断探索或转发解析是否正在执行、进展到哪里，以及是否需要采取操作。

每个任务显示任务类型、所属项目或链接、当前状态、执行阶段、数量进度和来源覆盖情况。失败详情、取消与重试操作在对应任务需要时出现，并与该任务状态保持相邻。界面不展示模型内部思考、内部提示词、工具原始日志或按轮次浏览入口。

关闭应用窗口不结束正在运行的任务；重新打开后，界面读取并显示当前状态。探索运行期间，新转发可以开始解析，不需要等待整轮探索结束。

## 正常流程

### 阅读素材

1. 用户打开应用，进入统一素材列表。
2. 用户通过标题列表浏览素材，按需使用顶部搜索或筛选。
3. 用户选择“开始阅读”，从当前结果第一条进入阅读流；或者点击具体标题，从该条进入同一阅读流。
4. 阅读流聚焦当前素材，依次呈现正文与图片、AI 通用理解，以及探索素材的项目参考；原链接位于来源信息附近。
5. 用户需要核验时打开原链接，通过顶部“上一条”和“下一条”继续阅读当前列表中的素材。
6. 用户选择“返回列表”，回到进入前的列表及原位置。

### 发起探索

1. 用户进入探索任务界面并选择本机项目。
2. 用户选择产品探索或 UI/UX 探索，查看用途、平台范围和可用状态。
3. 用户直接复用已有基线，或选择重新生成并完成预览与替换确认；缺少对应基线时，系统自动生成并继续。用户在预览中取消时回到探索表单，本次探索不自动继续。
4. 用户启动探索并查看当前进度。未配置或不可用的来源明确显示未覆盖，其余来源继续执行。
5. 探索在窗口关闭后继续，重新打开应用时恢复当前状态展示。
6. 入选素材进入统一素材列表，用户按素材阅读流程逐条查看。
