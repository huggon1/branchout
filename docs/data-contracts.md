# Branchout 数据与消息契约

> 目标设计：本文定义目标系统的逻辑数据与跨模块消息约定，不代表当前代码已经实现。产品行为以 [产品规格](product-spec.md) 为准，界面行为以 [UX 规格](ux-spec.md) 为准。

本文只规定模块协作必须共享的含义与边界。数据库表、文件格式、IPC 路径、进程通信技术和具体 TypeScript 类型由实现决定，但实现必须保持本文的字段语义与数据所有权。

## 模块边界

| 协作边界 | 调用方 | 返回方 | 结果归属 |
| --- | --- | --- | --- |
| 平台能力状态、搜索候选、详情读取 | Agent 工作进程 | 平台接入 | 平台接入只返回规范化结果，不保存素材 |
| 平台通用理解、项目参考 | 探索或转发任务处理器 | 内容理解模块 | Agent 工作进程组合结果，不写本地数据 |
| 任务进度、素材草稿、任务结果 | Electron 桌面主进程 | Agent 工作进程 | 主进程校验并持久化，工作进程不拥有数据 |
| 任务命令、状态快照、素材阅读数据 | 界面进程 | Electron 桌面主进程 | 主进程是事实来源，界面不直接执行工具或写存储 |

转发入口与内容平台的产品关系以 [产品规格](product-spec.md#转发获取与内容理解) 为准，Pi 会话及运行职责以 [架构总览](architecture-overview.md#技术组合) 为准。本文只约定这些行为跨模块传递时的数据边界。会话标识、提示词、模型思考和工具原始日志不进入素材记录，也不作为界面消息传递。

## 模型连接与凭据边界

主进程向界面返回 `ModelConnectionSummary`，只包含当前连接的公开状态：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `method` | 必需 | `generic_api` 或 `codex_subscription` |
| `status` | 必需 | 未配置、需要登录、可用或不可用 |
| `modelId` | 已选择时必需 | 当前模型标识 |
| `baseUrl` | 通用 API 时必需 | 当前服务地址；不包含 URL 中的秘密查询参数 |
| `api` | 通用 API 时必需 | `openai-responses` 或 `openai-completions` |
| `hasCredential` | 必需 | 是否已经保存凭据的布尔状态，不返回凭据内容 |
| `accountLabel` | Codex 登录后按需 | Codex 返回的非敏感账号标识；不由 Branchout 从令牌中推导 |
| `message` | 按需 | 用户可理解的配置、登录或刷新状态，不包含原始认证错误与秘密值 |

界面提交新的通用 API 配置时可以携带一次 API Key，主进程接收并转入受保护存储后，不把该字段写回响应、普通配置文件或界面状态。未提供新 API Key 表示保留已有凭据，不能靠回显旧值完成编辑。

Codex 模型目录由登录后的 Codex 客户端查询产生，每项至少包含模型 ID、用户可读名称和当前可选状态。主进程还必须校验模型是否受当前 Pi 运行时支持，但 Pi 内置或缓存目录不是账号授权来源。登录成功和用户主动刷新会触发新查询；查询失败作为独立状态返回，现有选择可以保留，但不能把缓存项标记为已经由账号重新确认。

主进程创建任务时生成内部的 `ModelExecutionConfig`，只包含该任务启动 Pi 会话所需的连接方式、模型、接口和服务地址，以及执行期间所需的受控凭据访问。任务开始后该配置保持不变；保存新的当前连接只影响之后创建的任务。该配置是秘密承载边界，不属于 `TaskSnapshot`、任务实时通知、素材草稿或素材记录。工作进程不得把它或其错误对象原样写入进度、结果或日志。

主进程可以在运行任务仍引用旧连接时暂留对应凭据，但保留范围必须绑定这些任务的生命周期。最后一个相关任务结束后，且旧凭据已不再是当前连接所需凭据时，主进程清理它；不能为了保留历史连接而无限期保存。

以下内容在任何情况下都不能进入界面可读状态、素材、任务快照、实时通知或普通日志：API Key、访问令牌、刷新令牌、认证码、Cookie、认证文件内容，以及含有这些值的请求头或 URL。错误信息必须先在拥有凭据的边界内完成脱敏，再作为用户可理解的状态传递。

## 平台能力与搜索

平台接入分别报告搜索和详情读取能力，因为同一平台的两种能力可能具有不同的配置或登录要求。

### 能力状态

每个平台返回以下逻辑字段：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `platform` | 必需 | 稳定的平台标识和用户可读名称 |
| `searchCapability` | 必需 | 搜索为可用、需要配置或暂不可用 |
| `readCapability` | 必需 | 详情读取为可用、需要配置或暂不可用 |
| `configurationHint` | 按需 | 用户可理解的配置提示；不包含凭据、Cookie 或内部命令 |

搜索与读取状态独立判断。例如，平台可以允许读取公开链接，但搜索仍需要登录。

### 搜索返回

探索方案向平台接入发起搜索后，平台接入返回一次 `SearchResult`：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `taskId` | 必需 | 关联本次内部任务，不创建按轮次浏览入口 |
| `platform` | 必需 | 本次搜索的平台 |
| `outcome` | 必需 | `results`、`no_results`、`not_covered` 或 `failed` |
| `candidates` | 有结果时必需 | 规范化候选列表；其他结果为空 |
| `message` | 非成功时必需 | 可保存并展示的简短原因，不包含原始日志 |

四种结果含义不能互换：

- `results`：搜索已执行并返回候选。
- `no_results`：搜索已正常执行，但没有候选。
- `not_covered`：本次未执行搜索，例如能力未配置或暂不可用。
- `failed`：已尝试执行，但发生错误。

每个 `SearchCandidate` 至少包含：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `platform` | 必需 | 候选来源平台 |
| `sourceUrl` | 必需 | 可交给详情读取的原始链接 |
| `title` | 按平台能力提供 | 来源返回的标题；未知时保持缺失，不生成貌似来源原文的标题 |
| `snippet` | 按平台能力提供 | 平台返回的候选摘要，只用于筛选，不冒充正文 |
| `publishedAt` | 按平台能力提供 | 来源声明的发布时间 |

搜索候选不是素材记录。只有候选入选并完成详情读取与所需理解后，主进程才接收一条待保存的素材结果。

## 详情读取与来源快照

Agent 工作进程把候选或转发链接交给平台接入读取。平台接入返回一次 `ReadResult`：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `taskId` | 必需 | 关联当前内部任务 |
| `platform` | 必需 | 负责读取的平台 |
| `sourceUrl` | 必需 | 用户可打开核验的原链接 |
| `outcome` | 必需 | `content`、`not_covered` 或 `failed` |
| `content` | 读取到内容时必需 | 规范化的来源快照 |
| `message` | 未读取到内容时必需 | 可展示原因，不包含凭据或原始日志 |

`SourceContent` 是某次读取获得的来源快照：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `sourceUrl` | 必需 | 原链接，不作为跨任务去重键 |
| `platform` | 必需 | 内容来源平台 |
| `title` | 按来源提供 | 来源明确给出的标题；未知时保持缺失 |
| `contentBlocks` | 必需 | 按来源阅读顺序排列的正文段落与图片引用；只保存实际获取的内容 |
| `images` | 必需 | 被图片块引用的图片内容或持久引用；无图片时为空 |
| `sourceIdentity` | 按来源提供 | 作者、站点或账号等来源身份 |
| `publishedAt` | 按来源提供 | 来源声明的发布时间 |
| `fetchedAt` | 必需 | 本次读取时间 |
| `completeness` | 必需 | `complete`、`partial` 或 `unknown` |
| `completenessNote` | `partial` 或 `unknown` 时必需 | 已知缺失范围，或无法判断完整性的原因 |

正文段落和图片通过 `contentBlocks` 保留相对顺序，图片块明确引用对应图片项，使阅读层可以恢复来源中的图文关系。二进制文件、缓存路径或远程引用采用何种存储方式由实现决定。`partial` 表示已经取得可保存内容但确认存在缺失；`unknown` 表示取得了可保存内容但无法可靠判断是否完整。两者都与完全未执行的 `not_covered` 和读取失败的 `failed` 分开。

## 内容理解输出

内容理解模块只基于已经获取的来源快照生成结果。来源快照、AI 通用理解和项目参考是三个独立部分。

### AI 通用理解

所有转发素材和探索素材都包含 `GeneralUnderstanding`：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `content` | 必需 | 对来源内容的可读理解；包含简明概括，并可按平台与内容形态扩展所需章节 |

通用理解不加入项目判断，也不补写未获取的来源内容。其内部章节不固定为统一的摘要加要点模板；不同平台可以演进各自适合的表达，阅读层按保存的结构呈现。

### 项目参考

只有探索素材包含 `ProjectReference`：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `relevanceReason` | 必需 | 该素材为什么与当前项目相关 |
| `referencePoints` | 必需 | 哪些具体内容值得项目参考 |

项目参考使用本次探索对应的项目基线和方向生成。转发素材不带项目、探索方向或项目参考，也不从链接内容推断这些信息。

## 独立素材记录

`MaterialRecord` 是主进程保存和界面读取的单条素材边界。每次转发，以及每个在探索中入选并完成处理的候选，分别产生一条新记录。

| 字段 | 必要性与适用范围 | 含义 |
| --- | --- | --- |
| `materialId` | 保存时必需 | 本条素材记录的唯一标识 |
| `taskId` | 必需 | 关联产生记录的内部任务；不等于新增任务历史界面 |
| `resultId` | 必需 | 当前任务内一次逻辑素材结果的稳定标识，用于安全接收重复消息 |
| `category` | 必需 | `forwarding`、`product_exploration` 或 `uiux_exploration` |
| `platform` | 必需 | 列表识别用的平台 |
| `collectedAt` | 必需 | 本条记录进入素材库的时间 |
| `displayLabel` | 必需 | 列表识别文本；优先使用来源标题，标题未知时透明使用来源身份或链接信息，不冒充来源标题 |
| `source` | 必需 | 独立保存的 `SourceContent` 来源快照 |
| `generalUnderstanding` | 必需 | 独立保存的 `GeneralUnderstanding` |
| `forwardingEntry` | 仅转发 | `app`、`feishu` 或 `telegram`，说明接收入口 |
| `repository` | 仅探索 | 稳定的项目标识与用户可读仓库名称 |
| `projectReference` | 仅探索 | 独立保存的 `ProjectReference` |

保存遵循以下边界：

- [产品规格](product-spec.md#转发获取与内容理解)规定的每次独立收集分别创建记录；原链接不是记录身份，也不用于跨任务自动合并或覆盖。
- 同一任务重复投递同一个 `resultId` 时，主进程关联已有 `materialId`，不再创建记录。新的逻辑收集使用新的 `resultId`，即使链接相同。
- 来源快照即使为 `partial` 或 `unknown`，只要取得了可阅读内容并完成所需理解，仍可保存，同时保留对应完整性说明。
- `not_covered` 或 `failed` 保存在任务与来源覆盖状态中；没有取得可阅读内容时，不伪造素材正文或 AI 通用理解。
- 搜索候选、任务日志和模型中间过程不进入素材记录。
- 主进程在素材记录持久化成功后才把该条计入已入库进度，并向界面通知新的 `materialId`。

## 任务状态与进度消息

主进程保存任务状态，Agent 工作进程通过消息报告进度和结果，界面通过受控接口读取主进程状态。探索和转发可以并行执行；具体并发数量由主进程控制。

### 任务快照

`TaskSnapshot` 至少包含：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| `taskId` | 必需 | 跨进程关联同一任务的内部标识 |
| `kind` | 必需 | 基线生成、探索或转发 |
| `target` | 必需 | 界面识别任务所需的目标：基线和探索包含项目，探索另含方向，转发包含目标链接和接收入口 |
| `state` | 必需 | `queued`、`running`、`awaiting_user`、`completed`、`failed` 或 `cancelled` |
| `phase` | 必需 | 用户可理解的当前阶段，不暴露模型思考或工具日志 |
| `progress` | 必需 | 适用于当前任务的数量进度 |
| `coverage` | 探索时必需 | 各平台当前搜索阶段及最终覆盖结果 |
| `updatedAt` | 必需 | 最近一次持久化更新时间 |
| `message` | 按需 | 用户可理解的等待原因、失败原因或下一步 |

每个平台的覆盖项包含 `platform`、当前阶段和按需出现的最终结果。当前阶段为 `pending`、`searching` 或 `finished`；只有该平台的全部搜索轮次结束后，才记录最终结果：任一轮得到候选为 `results`，全部已执行轮次正常完成但没有候选为 `no_results`，没有执行任何搜索为 `not_covered`，已尝试但未得到结果且搜索失败为 `failed`。任务刚创建时可以全部为 `pending`，多轮搜索期间保持 `searching`，不能提前用 `no_results` 表示尚未完成。

探索的 `progress` 分别记录已发现候选、已完成读取、已成功入库和处理失败的数量。总量尚未确定时可以为空，不能用虚构总数制造完成比例。转发使用相同含义记录单条处理进度。

`taskId` 用于把工作进程消息、主进程状态和界面展示关联起来。它是内部执行标识，不改变产品“不提供按探索轮次浏览入口”的规则。

### 消息顺序与恢复

1. 界面通过 preload 暴露的受控接口向主进程提交任务命令。
2. 主进程先创建并保存初始 `TaskSnapshot`，再把任务输入交给 Agent 工作进程。
3. 工作进程发送阶段进度、平台覆盖结果和逐条素材结果；消息均带同一 `taskId`，逐条素材结果另带稳定的 `resultId`。
4. 主进程校验消息。收到素材结果时，按 `taskId` 与 `resultId` 幂等保存或关联独立 `MaterialRecord`，再更新任务进度并通知已打开的界面。
5. 工作进程完成或失败后，主进程先保存最终任务状态，再通知界面。
6. 窗口关闭不终止主进程中的后台任务。界面重新打开时主动读取主进程保存的任务快照和素材列表，不依赖错过的实时事件恢复状态。

实时通知用于减少等待感，持久化快照才是重开后的事实来源。界面不直接调用平台、Pi 或本地存储。

## 基线重新生成预览

重新生成的业务规则以 [产品规格](product-spec.md#项目与基线) 为准。跨模块传递时，工作进程返回一份与当前基线分开的 `BaselinePreview`，至少包含项目、基线种类、预览内容和关联任务标识；主进程以 `awaiting_user` 表示任务正在等待确认。

主进程只在收到明确的“替换”命令后更新当前基线；“取消”只结束本次预览并保留旧基线，不隐含继续探索的命令。若预览由探索入口发起，取消后界面恢复原探索表单；确认完成前不得把预览交给探索任务使用。

## 一条链接形成两条记录的例子

下面使用虚构公开地址 `https://example.com/articles/branching-notes` 说明保存边界。示例中的“普通网页”只是占位来源，不承诺首版平台范围。

### 第一次：用户从 Telegram 转发

- Branchout 创建转发任务 `task-forward-01`，通过普通网页读取能力取得标题、正文和一张图片。
- 内容不需要任何项目上下文，只生成适合该网页内容的 AI 通用理解。
- 主进程保存素材 `material-101`：类别是“转发”，入口是“Telegram”，包含平台、收集时间、来源快照和 AI 通用理解。
- 这条记录没有仓库、探索方向或项目参考。

普通人看到的是：“我转发了一篇文章，Branchout 保存了原文和图片，并告诉我文章本身讲了什么。”

### 第二次：同一地址入选产品探索

- 项目 `example/branchout-demo` 的产品探索再次发现同一地址，并独立读取当时的内容。
- 内容理解仍生成一份只解释文章本身的 AI 通用理解，随后依据该项目的产品基线生成项目参考，例如“文章中的分支式阅读方式可用于比较当前素材阅读流”。
- 主进程保存新的素材 `material-208`：类别是“产品探索”，包含仓库名称、独立来源快照、AI 通用理解和项目参考。
- `material-101` 与 `material-208` 保持为两条记录；任一记录的更新都不覆盖另一条。

普通人看到的是：“同一篇文章后来又被项目探索找到，这次除了文章本身的解释，还说明了它为什么值得当前项目参考。”

### 打开阅读页

两条记录都进入统一素材列表，但各自保留自己的类别、时间和上下文。用户打开后看到：

| 阅读内容 | `material-101` 转发记录 | `material-208` 产品探索记录 |
| --- | --- | --- |
| 起始信息 | 普通网页、转发、收集时间和同一个原链接 | 普通网页、产品探索、收集时间、仓库 `example/branchout-demo` 和同一个原链接 |
| 来源内容 | 第一次读取保存的正文与图片，并显示当时的完整性 | 第二次读取保存的正文与图片，并显示当时的完整性 |
| AI 通用理解 | 解释文章本身讲了什么 | 独立解释文章本身讲了什么 |
| 项目参考 | 不显示 | 说明文章为什么与示例项目相关、哪些内容值得参考 |

这样，用户既能从原链接核验来源，也能分清“来源原文”“AI 对文章的理解”和“文章对当前项目的参考点”。
