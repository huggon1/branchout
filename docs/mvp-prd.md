# nature-feed MVP 产品需求

本文描述已确认的产品行为与验收规则；当前可运行能力以[根 README](../README.md)为准。视觉语言以[视觉设计指引](../DESIGN.md)为准，[页面设计](design/README.md)说明页面职责与参考资料，页面行为以本文为准。

## 1. 目标与范围

面向个人开发者和小团队产品构建者，以 GitHub 仓库为上下文，发现值得阅读的外部产品、需求和具体做法，人工选材后生成可阅读、可复制的 Feed。相关性围绕产品服务对象、痛点和使用场景判断，技术栈相同本身不足以入选。

两条业务流程彼此独立：

1. 在手机浏览不同平台时顺手留下有意思的内容，不打断当前阅读，之后集中查看原始内容和摘要。当前通过粘贴或 Telegram／飞书机器人转发 GitHub、小红书链接实现，接入渠道不定义目标人群。
2. 绑定仓库 → 手动生成仓库分析 → 多选仓库与探索角度，手动探索 → 素材库选材 → 按可配置提示词逐条生成 → 保存分章 Feed。

仓库分析和探索分别由用户手动发起；探索不会自动刷新仓库理解。支持绑定多个仓库，每个仓库独立分析，每个“仓库 × 探索角度”组合独立搜索，不做多仓库联合推理。转发内容不进入素材库、不参与 Feed 生成，探索完成后不自动生成 Feed。

首版不提供自由主题、用户创建或编辑探索模板、仓库理解确认或纠正、定时执行、跨来源语义合并、自动发布、学习主题管理、回忆练习、手工编辑生成正文、团队协作或移动端适配。

## 2. 术语与入口

| 名称         | 含义与入口                                                         |
| ------------ | ------------------------------------------------------------------ |
| 转发收件箱   | 独立粘贴、解析与阅读入口                                           |
| 项目回顾     | 仓库绑定、仓库理解及近期变化分析入口                               |
| 仓库理解     | 产品定位、服务对象、痛点、核心场景和必要约束；带版本和仓库依据     |
| 近期变化分析 | 对增量变更的独立产出，不进入素材库或自动成为探索角度               |

| 探索批次     | 一次操作产生的全部组合，显示总数、进度和汇总结果                   |
| 探索记录     | 单个仓库与角度组合的执行、平台结果、候选和依据，位于探索内         |

| 发现关系     | 素材来自哪个仓库、理解版本、探索角度和执行记录，以及各自的关联理由 |

| 我的 Feed    | 已保存成品的阅读、复制与来源追溯入口                               |

连接与模型设置为独立设置入口。AI 摘要忠于来源；发现理由说明与某个仓库的关系，两者分别展示。

## 3. 转发收件箱

支持粘贴链接或分享文案，以及 Telegram、飞书机器人接收本人私聊。每个渠道连接一个机器人，在应用生成十分钟有效的绑定码后，由用户在机器人私聊中完成绑定。未绑定用户、群聊和机器人消息不进入解析。

分享文案和支持的文本／富文本消息中，每条支持的链接分别形成记录；单条消息最多处理十条链接。平台重复投递不会重复入库，用户再次主动发送同一链接可以形成新记录。不解析截图、附件、合并聊天记录或其他平台链接。机器人回复接收情况及解析结果、简短 AI 摘要，完整内容在桌面阅读。回执失败不撤销已保存记录。

渠道配置位于「连接与模型」，显示连接、绑定、最近接收与失败情况，并提供停用和重新连接。长连接成功不代表消息权限已经验证，需通过真实私聊验收。应用运行且电脑清醒时接收；关窗驻留可继续接收，退出／睡眠不承诺持续在线或完整补收。

收件箱明确区分接收渠道与内容平台：GitHub 公开仓库支持 README 正文、图片、徽章、表格、代码和安全 HTML 结构；小红书支持可获取的正文与图片，需要平台登录，视频仅保留原文入口。记录显示来自粘贴、Telegram 或飞书。正文、媒体加载和 AI 摘要分别显示结果。

README 保留实际文件路径及可获取的版本，按该路径解析相对图片与链接。原文获取与模型摘要分离，不能用模型重写冒充完整 README。图片支持预览，加载失败单独提示；超限截断标记部分解析。不能固定版本的回退读取需明确说明。脚本、嵌入应用不执行。

列表用于查看转发记录及解析状态、进入详情或删除记录。详情保留原始链接、标题、可获取的作者等基础信息、正文或 README、AI 摘要及媒体。图片可预览；视频提供原文入口，不做转写。

解析中显示进行状态；无法完整获取时标记“部分解析”，保留已获取内容。失败显示原因并支持重试。AI 摘要明确标识为模型生成，不当作完整原文。空列表提供粘贴链接入口。

## 4. 项目回顾与仓库分析

### 4.1 仓库绑定与主理解

用户通过系统目录选择器逐个绑定本机已有的 Git 工作目录。绑定状态、当前分支与 commit、仓库可读和分析成功分别显示；目录失效或不是 Git 工作目录时显示原因，不把不可读仓库当作空仓库。本机绝对路径不显示在项目卡片，不进入业务状态、模型提示或日志。

仓库分析开始时固定当前 checkout 的分支与 commit，只从该 commit 的 Git 对象读取文档、必要代码和变化；未提交或未跟踪文件、符号链接目标及 submodule 内容不进入分析。之后结合固定仓库版本的当前内容和变化核对更新，不仅拼接旧摘要。理解区分仓库事实、模型推断和信息不足，保留文件、commit 或 change 依据。它不是代码审计报告，不因依赖 React 等框架就推导产品兴趣。

项目回顾显示理解版本、生成时间、所基于的分支和 commit，以及独立的近期变化分析记录。文件和变更证据在应用内按固定 commit 查看，不跳转到会漂移的工作树。工作树切换分支后重新分析前必须确认，取消时保留原绑定；detached HEAD 作为明确状态显示。首版无理解确认、手工修改或纠正功能。信息不足以判断产品时显示原因，不能猜测完成；失败保留上次成功理解。模型生成内容明确标识。

旧版 GitHub 项目保留历史理解与证据的只读访问，重新分析前要求选择本机目录。只有旧分析边界 commit 是新目录当前 commit 的祖先时才沿用项目身份；历史被重写或边界不可达时创建独立项目，不静默接续。

### 4.2 项目概览与增量开发时间线

首次点击“看看这个项目”，之后点击“看看最近进展”，未完成时可以“继续分析”。本版没有对话、定时执行或主动消息。概览以一段产品定位和 1–3 个核心使用情境说明为什么需要这个项目：用户正在做什么、希望获得什么结果、项目如何帮助完成。人群身份无依据可留空，不从接入渠道反推用户画像；不罗列点击步骤、内部阈值或校验机制。关键使用边界可展开，不强制输出建议、追问或泛化收益。

开发时间线首次整理最近 7 天，明确不含更早历史；之后从上次完整处理边界继续。按共同目标和行为合并 commit／PR，一个 PR 可包含多个独立进展；发布前归并跨批次重复的产品进展，保留原始记录。每项变化区分产品进展与实现记录：只有改变用户能力、核心使用方式或项目方向的条目进入“值得关注的进展”，首页倒序显示 10 条简短说明及可展开来源。日常修复与维护按目标合并，在分析记录中查询，不强制生成前后、取舍和验证章节；允许没有值得展示的进展。历史未分类条目保持在分析记录，不重新解释或删除。后续修复或撤回新增条目并关联旧进展，不改写历史。条目日期使用关联提交的变更时间，分析时间独立保存。

概要与时间线分别完成：概要成功即可用于探索；变化完整处理后才推进变化边界。失败、取消、中断保留已完成阶段与固定结束版本，继续分析不重复已完成的批次。无新变化与有变化但没有需展示的产品进展分别说明；未读完不能当成没有值得记录的进展。运行期间的新变化留给下一轮。

素材探索固定概览与时间线快照。从概览需求与使用情境出发，附带最近 5 条产品进展简短索引，可忽略。仅遇到会影响选材且概览无法回答的问题时，检索全部历史（含实现记录）、每次展开 1–3 条，最多 6 次项目上下文操作且计入探索总预算。实际使用的进展随发现关系保存。仓库知识解释相关性，外部正文支持来源事实，两者不能混用；没有新进展也能使用概览探索。仓库进展不自动成为素材或改变用户选择的角度。

## 5. 探索

### 5.1 配置与版本依据

用户多选仓库、探索角度和来源平台，默认时间范围为最近一周。启动前展示组合数量，如 2 个仓库、3 个角度产生 6 项探索。每批最多 10 项，逐项执行，失败项不阻塞其他组合。点击开始后立即确认已接收并禁止重复提交；批次持久化成功后进入独立运行详情页，历史批次从探索入口重新打开。

每个仓库明确显示本次使用的理解版本、生成时间、引用和 commit；未检查远端时不标“最新”。无可用理解的仓库提示先去项目回顾运行分析，不在探索中自动代办。启动后固定理解、模板版本、平台配置和时间范围；后续分析更新不改变本次依据。探索模板及其启动提示词内置，首版不可创建或修改；生成 Feed 的提示词单独配置。

### 5.2 五类探索角度

默认勾选前两类，其余按需选择。每类都按产品场景判断相关性，时间规则遵循下一节。

| 角度               | 收集目标                                                           | 入选边界与排除条件                                                                 |
| ------------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 相似产品与替代方案 | 解决相同或相邻痛点的产品、服务、开源项目、人工办法和工具组合       | 同类用户但不同问题须有相邻场景、互补或替代关系；仅行业、人群或技术栈相同不足以入选 |
| 用户需求与痛点     | 相关场景中的求助、抱怨、未满足需求和临时解决办法                   | 依赖实际用户表达，不推断“用户一定需要”，不泛收同类人群所有讨论                     |
| 产品设计与使用体验 | 首次使用、结果呈现、纠错、协作、信任等具体流程的做法               | 可跨领域借鉴，但必须指出相同交互问题；排除无场景的设计原则或纯视觉展示             |
| 获客与付费         | 相关用户如何发现、比较、试用、购买或放弃产品，及具体传播与收费尝试 | 排除通用增长技巧、无依据收入故事和无关人群案例                                     |
| 新工具与能力       | 改善产品功能的新服务、接口、开源能力或重要更新                     | 必须关联具体需求；开发、测试、部署工具仅在仓库有明确相关约束时入选                 |

各模板定义研究问题、平台表达策略、入选证据和排除条件，不能只换标题、套用同一组技术关键词。素材可命中多个角度，分别保存理由；探索之间不做多个仓库联合推理。

### 5.3 来源与时间范围

目标来源为 GitHub、小红书和 X，本版不提供通用网页搜索。用户选择本次启用的平台，显示各自可用状态和已验证的时间选项。GitHub 外部探索使用仓库搜索；绑定仓库的 PR、commit 和文件读取属于仓库分析能力。

一周是回溯基准，不是执行计划。按平台实际支持的原生时间条件检索，展示实际使用的范围和时间依据，不承诺任意日期过滤。旧产品在窗口内的新版本、新讨论可以入选；旧资料可作背景，不能包装为近期动态。

发布时间、近期活动时间、采集时间分别记录。最近推送不等于功能发布，累计点赞或 star 不证明本周热议；缺少窗口内活动证据的候选标待确认，不作为近期发现入库。缺失指标不当作零，各平台原生指标不能换算成统一热度分。数量上限是上限，不是交付配额。

### 5.4 多步搜索与停止

每个组合围绕固定主理解和角度运行 Agent 搜索循环：理解研究问题与消歧 → 按平台和目标社区选择语言、表达及查询 → 搜索与读取 → 判断相关性和证据缺口 → 改词、补搜或进一步核实 → 保存素材与依据。

语言选择根据目标社区，而非中文输入统一译成英文或所有平台使用同一词串；读取候选中的实际用语可用于下一轮。首轮无结果先检查表达、歧义及合理替代查询，不立即认定该方向没有内容。Agent 可在本组合启用的平台内根据发现补足证据，不能增加未选平台或扩大时间范围。

结束依据分别记录：

- 关键问题已有证据且新增相关内容趋少；
- 合理的不同表达已尝试，仍缺少足够材料；
- 平台受阻或正文读取不足，覆盖有限；
- 平台阻塞使必要证据无法取得；
- 用户暂停、结束或应用退出。

不以搜索次数、素材条数或模型一句“充分”代替覆盖与证据检查。不承诺穷尽平台。新探索不设置查询、读取、候选、模型调用、规划步骤或总耗时的固定完成上限：新的规范来源、完成候选判断、补全正文／时间依据或新增受支持／受阻缺口均算证据进展；仍有证据进展就继续。已有充分覆盖并连续行动的边际收益降低后完成。无结果只在各启用平台的合理不同策略正常完成且没有平台阻塞时成立。

重复同一行动、在两种行动间往返或持续没有可提交进展时进入可恢复的“为保护进度已暂停”，不能算成功或一般失败。单次模型与平台调用仍保留超时、AbortSignal、provider 上下文与输出上限；隐私检查、来源身份、幂等和 provider／限流／登录错误分类不变。

执行记录显示研究方向、平台与查询语言、查询、候选数、读取状态、判断与摘录、入库数、用量和停止原因，不展示模型内部思维。候选区分相关、排除和待确认；只有相关且证据有效、满足实际筛选条件的候选入库。平台失败不能表述为“没有相关内容”。

### 5.5 失败与重试

运行生命周期区分正在创建、排队、进行中、已暂停、已完成、部分完成、平台受阻、用户结束、为保护进度已暂停、失败和重启后待继续；证据结果与停止原因另行保存。批次和单项均可暂停／继续，重启后绝不自动运行。已保存的成功结果在同批其他项运行时即可阅读，继续沿用原理解版本与配置且不重复生成发现关系；要使用新版本，用户发起新探索。模型不可用显示原因，不悄悄改成固定关键词搜索。

运行详情显示队列、阶段、当前行动、最近 3–5 条事实事件、有效证据进展、剩余缺口、下一行动依据、覆盖、阻塞和结果。不显示模型内部思维。调用、查询、补读和候选按事实累计；token 只显示服务商实际报告值，缺失时明确显示不可用，不能伪造为 0。

## 6. 素材库与发现关系

### 6.1 内容和依据

素材包含来源身份、原始链接、标题、可获取的作者与时间、正文、完整度、原生指标和 AI 摘要。摘要忠于来源，不混入某个仓库的专属评价。正文不足标部分解析；摘要失败不阻止原文阅读，可重试。缺乏证据的评论共识或趋势不得生成。

同一来源重复发现时卡片去重，保留全部发现关系。每个关系包含仓库、所用理解版本、探索角度与模板版本、执行记录、关联理由和原文摘录。A 仓库的“相似产品”和 B 仓库的“用户痛点”不能互相覆盖；同一产品的官网、GitHub 仓库和用户帖子仍是不同素材，不做跨来源语义合并。

同日覆盖、跨日保留底层采集记录；列表先按筛选条件选择记录，再按来源去重显示最近一条，发现关系仍可跨日查看。已选素材固定到选中记录，不随列表刷新切换。无论采用何种存储方式，同一份 Feed 中同来源只生成一次，历史依据保持不变。

### 6.2 浏览与选材

支持按仓库、探索角度、批次、平台、日期和是否已生成筛选，卡片标明重复发现的仓库与角度，展开查看各自理由和记录。单平台按原生指标排序，默认按收集时间倒序。

跨仓库、角度和日期多选素材；切换筛选保留已选，全选只作用于当前筛选结果。可在已选清单核对并移除，允许再次使用已有素材并显示已使用提醒。区分空库与筛选无匹配。

来源相同的不同采集记录在本次选材中只保留一项，明确实际使用的内容和发现依据，不静默切换快照。删除素材不改变历史 Feed 的内容与来源依据。

## 7. Feed 生成与阅读

### 7.1 配置与章节

沿用人工选材后生成，每条素材独立处理。默认按探索角度分章，每条素材只出现一次；多重角度归属默认选择一个主要归属，用户可在选材时调整。章节与条目顺序在生成前明确可见，筛选不会悄悄重排。条目标明相关仓库，并保留原文与发现理由入口。

提供默认中文生成提示词，可修改并记住上次配置。提示词控制表达，不改变已选素材、章节归属、顺序或证据要求。未选素材不能生成，不提供用户提示词库。

生成输入使用保存的原始素材与本次选定的发现依据，不只读取 AI 摘要。默认轻量总结该素材内容及其产品关联，不要求跨来源综合结论或完整分析报告。

### 7.2 可空缺的产出与恢复

| 情况                   | 行为                                        |
| ---------------------- | ------------------------------------------- |
| 某角度无合适素材       | 探索记录显示无结果，不降低条件              |
| 未选某角度素材         | Feed 不出现该章                             |
| 素材不足以支撑生成要求 | 该条标依据不足，不补写事实                  |
| 模型错误或中断         | 标失败或中断，保留成功项并支持重试          |
| 某章全部无法产出       | 成品省略空章，生成状态保留原因与处理入口    |
| 全部无法产出           | 保留选材与提示词，不保存为成功的可阅读 Feed |

依据不足与执行失败不同；单纯重试不保证补足证据。用户可以调整提示词、重新选材或重新探索。部分成功内容可读、可复制，复制提示未包含的失败项。

生成时固定正文、发现关系、理解与模板版本、章节、顺序和提示词。仓库再次分析、素材更新或删除后，历史 Feed 保持生成时内容与证据。

### 7.3 我的 Feed

历史列表展示标题、生成时间和状态；详情支持分章阅读、逐条或整份复制、打开来源、查看发现依据、返回列表与删除。复制包含原始链接并反馈成功或失败。

修改提示词重新生成整份时保存为新 Feed，明确展示所用历史来源快照；单条重新生成成功后替换当前结果，失败保留原结果。不提供生成正文手工编辑、拖拽编排或通用版本管理界面。

## 8. 连接、桌面与数据边界

应用提供小红书和 X 所需连接状态、登录或配置入口；GitHub 公开能力仅用于转发解析和外部探索，不承担项目仓库读取。首版各外部平台一个连接身份，用户按需完成登录和平台验证，无需操作 CLI。连接成功与各能力可用性分别检查；失效停止自动重试，不自动更换模型、平台或计费方式。本机项目通过系统目录选择器接入，不配置 GitHub Token，也不自动 clone、fetch、pull 或 checkout。

通过独立设置入口配置模型及平台连接。可以保存多个模型连接，明确选择一个供所有 Agent 功能使用；不自动换模型或切换计费方式。自定义 API 支持连接名称、服务地址、API Key、模型名称及 OpenAI 兼容的 Chat Completions／Responses；Codex 订阅提供登录入口、动态模型列表与刷新。两种方式均可通过正式调用链测试连接，保存、测试和启用分别操作，未保存修改在离开或切换时提醒。

业务数据在本机保存；固定 commit 的必要内容会发送到用户配置的模型服务，本地保存不等于离线处理。本机仓库对外探索只使用抽象后的产品需求和场景，不向搜索服务发送私有代码、内部标识、绝对路径或凭据。

已确认视觉方向为白色、冷灰与蓝色；正文与 Feed 安全渲染 Markdown，常见 HTML 结构经白名单清洗，禁用脚本、事件处理器及嵌入应用。验证 1100×720、1280×800 和 1440×940 桌面窗口，图稿仅作页面设计参考。

关窗可驻留完成用户发起的工作；退出应用或关机停止，重启后把未完成探索标为“重启后待继续”，由用户手动继续，绝不自动运行。没有定时执行、错过计划或自动补跑入口。

旧任务、素材、转发和 Feed 数据须安全保留，不能伪造仓库或模板归属。旧任务在历史收集中只读查看且停止调度；无探索归属的旧素材默认归入“历史素材”章节。转发流程不因本次调整改变。

## 9. 核心验收场景

| 场景                           | 预期                                                  |
| ------------------------------ | ----------------------------------------------------- |
| 本机 Git 工作目录绑定          | 显示分支、固定 commit、读取与分析状态；绝对路径不外泄 |
| 分支切换或 detached HEAD       | 切换需确认且历史版本不变；detached 状态明确可理解     |
| 旧 GitHub 项目重新关联         | 历史只读；边界连续才沿用身份，否则建立独立项目        |
| 首次分析与随后增量分析         | 首次 7 天变化，完整处理后推进固定边界；无变化不凑条目 |
| 分析失败、取消或中断           | 保留已完成阶段，未完成变化不推进边界，可继续          |
| 探索使用旧理解                 | 显示准确版本；不自动运行仓库分析                      |
| 探索中生成新理解               | 进行中的探索和已有素材仍能追溯原版本                  |
| 两个仓库与三个角度             | 明确 6 项探索，分别记录状态和依据                     |
| 中英文平台搜索偏题             | 从已读结果发现歧义，改变表达后补搜，保留过程依据      |
| 平台限流、登录或 provider 失败 | 与无相关内容区分，成功结果保留并可继续                |
| 重复、摆动或长期无进展         | 安全暂停，保留检查点，手动继续                        |
| 旧产品本周有新动态             | 保留活动时间证据，不把旧介绍或累计指标当新动态        |
| 同来源被多个组合发现           | 卡片去重，各关联理由独立可见，Feed 只生成一次         |
| 跨筛选选材、多角度归属         | 保留选中项，可核对主章节、顺序和实际快照              |
| 某章或全部无法生成             | 不凑内容、不保留空章，完整保留生成状态与输入          |
| 新理解、模板升级或素材删除     | 历史 Feed 内容、章节与证据不变                        |
| 升级已有本地数据               | 历史可读可追溯，转发回归通过，调度不再自动执行        |

桌面验证窗口为 1100×720、1280×800 和 1440×940。正文与 Feed 安全渲染 Markdown；长标题、版本信息、重叠标记和错误提示不能遮挡操作。页面职责与既有图稿的适用范围见[页面设计](design/README.md)。
