# Feedloom MVP 产品需求

使用设计、白蓝视觉方向与五页设计图已由 huggon1 确认，设计图只提供视觉参考；平台、术语和配置以本文为准。本文描述产品行为，不代表当前应用已实现这些能力。

## 1. 目标与范围

面向个人、桌面使用。持续发现值得关注的信息，人工选材后生成适合自己阅读、也能直接复制用于知识分享或产品发现的 Feed。

两条流程彼此独立：

1. 粘贴或通过 Telegram／飞书机器人转发 GitHub、小红书链接 → 解析 → 阅读原始内容和 AI 摘要。
2. 配置收集任务 → 定时或手动收集 → 意图检索与可追溯筛选入库 → 跨任务、跨日期选材 → 按提示词逐条生成 → 汇总保存 Feed → 阅读和复制。

转发内容不进入素材库，不参与 Feed 生成。收集完成后不自动生成 Feed。

不包含：博主风格提取、独立主题管理、跨来源语义合并、综合总结、内容编辑、拖拽编排、自动发布、提示词库、版本管理界面、收藏、标签、归档、视频转写、团队协作、权限管理和移动端适配。

## 2. 统一用语与导航

| 显示名称   | 含义                                         | 页面位置               |
| ---------- | -------------------------------------------- | ---------------------- |
| 转发收件箱 | 接收的链接、原始内容和解析结果               | 主导航                 |
| 收集任务   | 关注方向及平台、时间和筛选配置               | 主导航                 |
| 收集记录   | 某个任务一次执行的状态与结果                 | 任务内查看，不占主导航 |
| 素材库     | 各任务、各日期积累的来源素材                 | 主导航                 |
| 素材       | 一个仓库、一篇帖子等单个来源在某日的收集结果 | 素材库和选材列表       |
| Feed 生成  | 人工选材、配置提示词并生成的工作台           | 主导航                 |
| 我的 Feed  | 已保存的生成成品                             | 主导航                 |
| AI 摘要    | 对来源内容的简短概括，不替代原文             | 素材和转发详情         |

界面不使用 Topic、Creator Profile 或 event。“任务”直接描述关注方向；“Feed”指一次生成保存的整份成品，其中包含独立的单条生成内容。

## 3. 转发收件箱

支持粘贴链接或分享文案，以及 Telegram、飞书机器人接收本人私聊。每个渠道连接一个机器人，在应用生成十分钟有效的绑定码后，由用户在机器人私聊中完成绑定。未绑定用户、群聊和机器人消息不进入解析。

分享文案和支持的文本／富文本消息中，每条支持的链接分别形成记录；单条消息最多处理十条链接。平台重复投递不会重复入库，用户再次主动发送同一链接可以形成新记录。不解析截图、附件、合并聊天记录或其他平台链接。机器人回复接收情况及解析结果、简短 AI 摘要，完整内容在桌面阅读。回执失败不撤销已保存记录。

渠道配置位于「连接与模型」，显示连接、绑定、最近接收与失败情况，并提供停用和重新连接。长连接成功不代表消息权限已经验证，需通过真实私聊验收。应用运行且电脑清醒时接收；关窗驻留可继续接收，退出／睡眠不承诺持续在线或完整补收。

收件箱明确区分接收渠道与内容平台：GitHub 公开仓库支持 README 正文、图片、徽章、表格、代码和安全 HTML 结构；小红书支持可获取的正文与图片，需要平台登录，视频仅保留原文入口。记录显示来自粘贴、Telegram 或飞书。正文、媒体加载和 AI 摘要分别显示结果。

README 保留实际文件路径及可获取的版本，按该路径解析相对图片与链接。原文获取与模型摘要分离，不能用模型重写冒充完整 README。图片支持预览，加载失败单独提示；超限截断标记部分解析。不能固定版本的回退读取需明确说明。脚本、嵌入应用不执行。

列表用于查看转发记录及解析状态、进入详情或删除记录。详情保留原始链接、标题、可获取的作者等基础信息、正文或 README、AI 摘要及媒体。图片可预览；视频提供原文入口，不做转写。

解析中显示进行状态；无法完整获取时标记“部分解析”，保留已获取内容。失败显示原因并支持重试。AI 摘要明确标识为模型生成，不当作完整原文。空列表提供粘贴链接入口。

## 4. 收集任务与收集记录

### 4.1 配置与管理

每个任务描述一个关注方向，可选择多个平台，不另设主题管理。

| 配置项             | 用途                                               |
| ------------------ | -------------------------------------------------- |
| 任务名称、关注描述 | 明确要收集什么                                     |
| 来源平台           | 勾选已接入平台，显示可用状态                       |
| 执行频率与时间     | 自行决定何时执行                                   |
| 平台时间范围       | 各平台分别配置，只提供接入验证通过的原生选项       |
| 平台筛选条件       | 按平台实际支持的信号设置门槛                       |
| 各平台每轮素材上限 | 各平台分别设置，任务总上限为各平台上限之和，不凑数 |

支持新建、修改、立即执行、暂停和删除。提示词不属于任务配置。删除任务保留已有素材和 Feed。

首版目标平台为 GitHub Trending、小红书和 X，三者均需真实收集验证；验证遇阻时与 huggon1 协作解决，不以占位入口替代交付。

| 平台   | 收集方式                             | 配置边界                                                                                                                |
| ------ | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| GitHub | 仓库搜索或 Trending 日、周、月榜     | 仓库搜索按关注方向检索，时间范围指最近推送；Trending 是榜单发现，意图模式可对榜单候选判断相关性；不以 Issue/PR 搜索替代 |
| 小红书 | 按意图规划的查询或固定关键词搜索帖子 | 使用实测可用的一天内、一周内等平台时间档位，不承诺任意日期范围                                                          |
| X      | 按意图规划的查询或固定关键词搜索帖子 | 时间范围和原生指标按适配器验证结果开放                                                                                  |

任务共享执行频率，各平台分别设置时间范围、筛选条件和最终素材上限。新任务默认意图收集：模型根据任务名称、关注描述和可选种子词消歧、规划多查询，读取候选后决定补搜。旧任务保留固定关键词模式，可在编辑时切换；不自动增加原定时任务的模型用量。固定关键词模式仍要求填写适用平台的搜索词。不收集关注流、推荐流或指定博主动态。执行频率不等于回溯范围，重复命中按同日覆盖、跨日保留处理。不保证穷尽平台在时间范围内的全部内容。

### 4.2 结果规则

意图模式先规划与检索候选，再结合原始内容判断相关性、摘取依据，并按平台指标门槛及最终数量上限入库。判断分为相关、排除、待确认；只有相关且满足门槛的候选进入素材库，其余保留在收集详情供检查。理由和摘录可追溯到来源，不把模型判断描述为客观质量分。信息不足时标记待确认；不合并不同来源。固定关键词模式保留规则筛选行为。模型摘要仍忠于来源、辅助人工选材。

不足数量上限时保留实际结果，不放宽门槛补足。每轮保留收集记录，可查看执行状态、各平台情况及相关素材。按天覆盖的素材显示更新后的内容，不承诺还原同日每一轮的历史快照。

收集记录区分进行中、成功、部分成功、无结果和失败。平台失败不能表述为“没有相关内容”。部分失败保留成功结果，支持重试失败部分。

意图收集限制搜索轮数、总查询数、候选数量、模型调用数和总耗时。达到预算或没有新的搜索方向时停止，数量不足不降低条件。模型不可用时显示失败，不悄悄改成关键词搜索。阶段显示规划、搜索、读取、筛选和保存，以及查询、候选数、入库数、停止原因；不展示模型内部思维。取消、重试和重启保留成功结果，历史 Feed 的来源快照不受影响。

编辑任务显示未保存状态，提供保存并执行，离开未保存草稿时明确处理。重新生成旧 Feed 时显示实际使用的来源快照，与新选材模式明确区分。

### 4.3 连接与模型设置

通过独立设置入口配置模型及平台连接，五项业务导航保持不变。设置页采用分组连接列表与配置详情，模型服务和来源平台各自展示状态与操作。可以保存多个模型连接，明确选择一个供所有 Agent 功能使用；不自动换模型或切换计费方式。

自定义 API 支持连接名称、服务地址、API Key 和自由输入的模型名称，接口类型支持 OpenAI 兼容的 Chat Completions 与 Responses。Codex 订阅提供登录入口、动态模型列表与刷新；只能选择官方列表中且当前适配器支持的模型，不把默认模型锁死。

两种方式均提供测试连接，通过正式模型调用链发送不含业务素材的短请求，并说明会消耗少量额度。登录状态与模型响应分别验证；错误区分认证失败、模型或接口不可用、额度受限和超时。展示测试时间、所测模型与耗时，配置修改后测试结果失效。保存、测试和启用分别操作；未保存修改在离开或切换时提醒，后台刷新不覆盖草稿。

一个平台首版连接一个账号。应用提供登录入口、状态检查、退出和重新登录；首次扫码和平台验证由用户完成。登录失效停止该平台自动重试，成功平台的结果保留。连接成功与解析、收集能力分别检查，不因登录成功就声称所有功能可用。用户无需手工操作 CLI。

## 5. 素材库

### 5.1 素材与同日覆盖

同一来源 URL 与同一收集日期对应一个素材。同日再次收集覆盖更新内容、摘要和指标；跨日期分别保留。同日被多个任务收集时共用素材，保留所属任务关系，按任一任务均能找到。

素材展示标题、平台、原始链接、可获取的作者与发布时间、收集日期与最近更新时间、所属任务、平台原生信号和 AI 摘要。来源发布时间与收集时间明确区分；缺失指标显示未提供，不当作零；设置该指标门槛时，缺失项不满足条件。

已经生成的 Feed 保持生成时的内容和来源依据，不随素材覆盖或删除而改变。

摘要帮助用户了解素材的具体内容和亮点，避免空泛套话。只依据已获取内容，不虚构评论共识或增长趋势。原文不完整时明确标记；摘要失败不影响原文阅读。摘要长度、表达风格和提示词通过真实素材逐步优化，不预设固定评审模板。Feed 生成使用保存的原始素材，不只读取摘要。

保持单条素材独立生成。检索候选与筛选记录属于收集运行，不作为跨来源信号聚合层，也不自动进入 Feed。

### 5.2 浏览与选材

默认按收集时间倒序。支持按任务、平台、日期和是否已用于生成筛选。选定单个平台后可按其原生指标排序；跨平台不提供统一热度分。

勾选素材后可进入 Feed 生成，也可直接在生成页选材，两处采用一致的列表体验。切换筛选保留已选素材，可在已选清单核对和移除。

允许重复使用，以“已用于生成”提醒，提供仅看未使用素材的筛选。可删除素材，不影响已有 Feed。区分库为空与筛选无匹配结果。摘要失败仍可查看来源信息并重试。

## 6. Feed 生成

### 6.1 选材与提示词

可浏览整个素材库，跨任务、跨日期勾选，支持全选、取消选择和已选清单。全选作用于当前筛选结果，切换筛选不清空先前选择；部分选中时显示半选状态。未选择素材时不能生成。

同一来源的不同日期素材可同时选择；提示重复来源，不阻止、不自动排除。每个选中素材独立处理，不做跨素材语义合并或综合总结。

提供默认生成提示词，生成前可修改，记住上次使用的配置。默认中文，可通过提示词改变语言与格式。不提供提示词库。

### 6.2 生成与保存

一条选中素材对应一条生成内容，按已选清单显示的顺序汇总，保存为有标题和生成时间的 Feed。生成前可核对实际顺序，切换素材筛选不悄悄重排已选清单。清晰展示生成进度及各素材的结果状态。

部分失败保留成功内容，标出失败项并支持重试；成功内容可阅读和复制。全部失败显示失败状态和重试入口，不伪装成可阅读成品。

生成内容保留到对应来源和收集记录的追溯入口。表达形式由提示词决定，不要求固定文案结构。

## 7. 我的 Feed

历史列表展示保存的 Feed。详情支持逐条阅读、打开来源、查看对应收集依据，并返回历史列表。

可复制整份或单条，包含各条对应的原始链接。部分成功时复制可用内容，并明确仍有失败项未包含。复制提供成功或失败反馈。

不提供手工编辑。修改提示词后重新生成整份，保存为新 Feed；单条重新生成替换当前结果，操作前明确提示。替换成功前保留已有内容，失败时允许重试。不做版本管理界面。

可删除 Feed；无历史时提供前往生成页的入口。

## 8. 核心验收场景

| 场景                              | 预期体验                                             |
| --------------------------------- | ---------------------------------------------------- |
| 粘贴支持的来源链接                | 阅读解析内容和标识清晰的摘要，或看到可理解的失败原因 |
| 转发仅获得部分内容                | 标记部分解析，保留原文入口                           |
| 某平台找到 7 条，该平台上限 20 条 | 入库 7 条，不降低条件凑数                            |
| 某平台失败，其他平台成功          | 保留成功结果，显示部分成功与失败平台                 |
| 同来源同日被两任务收集            | 一条结果，两个任务下均能找到，展示最新数据           |
| 同来源连续三天收集                | 三条结果，保留各日内容                               |
| 跨任务、跨日期选择后切换筛选      | 已选项保留，可核对和移除                             |
| 选择同来源两个日期的素材          | 提醒重复，仍分别生成                                 |
| 一批生成部分失败                  | 成功内容可阅读和复制，失败项可重试                   |
| 修改提示词重新生成整份            | 得到新 Feed，原 Feed 保留                            |
| 删除任务或素材                    | 已有 Feed 的内容和来源依据不变                       |
| 按原生指标排序                    | 单平台可排序，跨平台无统一热度分                     |

## 9. 页面设计与最终评审

已确认视觉方向：白色为主、冷灰分区、蓝色强调；加强字体对比、内容层级与操作辨识，收集列表紧凑，Feed 阅读排版宽松。正文与 Feed 安全渲染 Markdown，常见 HTML 结构经白名单清洗后展示，禁用脚本、事件处理器及嵌入应用；长标题、控件与提示不能相互遮挡。验证 1100×720、1280×800 和 1440×940 桌面窗口。五页设计图见 [页面设计评审](design/README.md)，图稿已确认；生图是页面设计参考，不代表可运行界面。
