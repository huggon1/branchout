# Feedloom MVP 产品需求

使用设计、白蓝视觉方向与五页设计图已由 huggon1 确认，并完成图文一致性检查。本文描述产品行为，不代表当前应用已实现这些能力。

## 1. 目标与范围

面向个人、桌面使用。持续发现值得关注的信息，人工选材后生成适合自己阅读、也能直接复制用于知识分享或产品发现的 Feed。

两条流程彼此独立：

1. 粘贴 GitHub 或小红书链接 → 解析 → 阅读原始内容和 AI 摘要。
2. 配置收集任务 → 定时或手动收集 → 规则筛选入库 → 跨任务、跨日期选材 → 按提示词逐条生成 → 汇总保存 Feed → 阅读和复制。

转发内容不进入收集库，不参与 Feed 生成。收集完成后不自动生成 Feed。

不包含：博主风格提取、独立主题管理、模型筛选隐藏条目、跨来源语义合并、综合总结、内容编辑、拖拽编排、自动发布、提示词库、版本管理界面、收藏、标签、归档、视频转写、团队协作、权限管理和移动端适配。

## 2. 统一用语与导航

| 显示名称 | 含义 | 页面位置 |
| --- | --- | --- |
| 转发收件箱 | 接收的链接、原始内容和解析结果 | 主导航 |
| 收集任务 | 关注方向及平台、时间和筛选配置 | 主导航 |
| 收集记录 | 某个任务一次执行的状态与结果 | 任务内查看，不占主导航 |
| 收集库 | 各任务、各日期积累的来源条目 | 主导航 |
| 收集条目 | 一个仓库、一篇帖子等单个来源在某日的收集结果 | 收集库和选材列表 |
| Feed 生成 | 人工选材、配置提示词并生成的工作台 | 主导航 |
| 我的 Feed | 已保存的生成成品 | 主导航 |
| AI 摘要 | 对来源内容的简短概括，不替代原文 | 条目和转发详情 |

界面不使用 Topic、Creator Profile 或 event。“任务”直接描述关注方向；“Feed”指一次生成保存的整份成品，其中包含独立的单条生成内容。

## 3. 转发收件箱

在应用中粘贴 GitHub 或小红书链接并发起解析，不提供手机系统分享或聊天机器人入口。

列表用于查看转发记录及解析状态、进入详情或删除记录。详情保留原始链接、标题、可获取的作者等基础信息、正文或 README、AI 摘要及媒体。图片可预览；视频提供原文入口，不做转写。

解析中显示进行状态；无法完整获取时标记“部分解析”，保留已获取内容。失败显示原因并支持重试。AI 摘要明确标识为模型生成，不当作完整原文。空列表提供粘贴链接入口。

## 4. 收集任务与收集记录

### 4.1 配置与管理

每个任务描述一个关注方向，可选择多个平台，不另设主题管理。

| 配置项 | 用途 |
| --- | --- |
| 任务名称、关注描述 | 明确要收集什么 |
| 来源平台 | 勾选已接入平台，显示可用状态 |
| 执行频率与时间 | 自行决定何时执行 |
| 回溯范围 | 自行决定查找多长时间范围内的内容 |
| 平台筛选条件 | 按平台实际支持的信号设置门槛 |
| 每轮最多收集条数 | 本轮入选条目总数上限，不是必须凑够的目标 |

支持新建、修改、立即执行、暂停和删除。提示词不属于任务配置。删除任务保留已有收集条目和 Feed。

以 last30days 为收集基础，但工具声明支持不等于应用已接入或可用。具体平台、时间范围和筛选选项按接入验证结果呈现，不承诺所有来源均可使用。

### 4.2 结果规则

先收集，再按明确规则筛选入库。模型只生成尽量客观的 AI 摘要，不替用户隐藏条目，不合并不同来源。热度和时间等信号不称为内容质量判定。

不足数量上限时保留实际结果，不放宽门槛补足。每轮保留收集记录，可查看执行状态、各平台情况及相关条目。按天覆盖的条目显示更新后的内容，不承诺还原同日每一轮的历史快照。

收集记录区分进行中、成功、部分成功、无结果和失败。平台失败不能表述为“没有相关内容”。部分失败保留成功结果，支持重试失败部分。

## 5. 收集库

### 5.1 条目与同日覆盖

同一来源 URL 与同一收集日期对应一个条目。同日再次收集覆盖更新内容、摘要和指标；跨日期分别保留。同日被多个任务收集时共用条目，保留所属任务关系，按任一任务均能找到。

条目展示标题、平台、原始链接、可获取的作者与发布时间、收集日期与最近更新时间、所属任务、平台原生信号和 AI 摘要。来源发布时间与收集时间明确区分；缺失指标显示未提供，不当作零。

已经生成的 Feed 保持生成时的内容和来源依据，不随条目覆盖或删除而改变。

### 5.2 浏览与选材

默认按收集时间倒序。支持按任务、平台、日期和是否已用于生成筛选。选定单个平台后可按其原生指标排序；跨平台不提供统一热度分。

勾选条目后可进入 Feed 生成，也可直接在生成页选材，两处采用一致的列表体验。切换筛选保留已选条目，可在已选清单核对和移除。

允许重复使用，以“已用于生成”提醒，提供仅看未使用条目的筛选。可删除条目，不影响已有 Feed。区分库为空与筛选无匹配结果。摘要失败仍可查看来源信息并重试。

## 6. Feed 生成

### 6.1 选材与提示词

可浏览整个收集库，跨任务、跨日期勾选，支持全选、取消选择和已选清单。全选作用于当前筛选结果，切换筛选不清空先前选择；部分选中时显示半选状态。未选择条目时不能生成。

同一来源的不同日期条目可同时选择；提示重复来源，不阻止、不自动排除。每个选中条目独立处理，不做跨条目语义合并或综合总结。

提供默认生成提示词，生成前可修改，记住上次使用的配置。默认中文，可通过提示词改变语言与格式。不提供提示词库。

### 6.2 生成与保存

一条选中条目对应一条生成内容，按已选清单显示的顺序汇总，保存为有标题和生成时间的 Feed。生成前可核对实际顺序，切换素材筛选不悄悄重排已选清单。清晰展示生成进度及各条目的结果状态。

部分失败保留成功内容，标出失败项并支持重试；成功内容可阅读和复制。全部失败显示失败状态和重试入口，不伪装成可阅读成品。

生成内容保留到对应来源和收集记录的追溯入口。表达形式由提示词决定，不要求固定文案结构。

## 7. 我的 Feed

历史列表展示保存的 Feed。详情支持逐条阅读、打开来源、查看对应收集依据，并返回历史列表。

可复制整份或单条，包含各条对应的原始链接。部分成功时复制可用内容，并明确仍有失败项未包含。复制提供成功或失败反馈。

不提供手工编辑。修改提示词后重新生成整份，保存为新 Feed；单条重新生成替换当前结果，操作前明确提示。替换成功前保留已有内容，失败时允许重试。不做版本管理界面。

可删除 Feed；无历史时提供前往生成页的入口。

## 8. 核心验收场景

| 场景 | 预期体验 |
| --- | --- |
| 粘贴支持的来源链接 | 阅读解析内容和标识清晰的摘要，或看到可理解的失败原因 |
| 转发仅获得部分内容 | 标记部分解析，保留原文入口 |
| 找到 7 条，上限 20 条 | 入库 7 条，不降低条件凑数 |
| 某平台失败，其他平台成功 | 保留成功结果，显示部分成功与失败平台 |
| 同来源同日被两任务收集 | 一条结果，两个任务下均能找到，展示最新数据 |
| 同来源连续三天收集 | 三条结果，保留各日内容 |
| 跨任务、跨日期选择后切换筛选 | 已选项保留，可核对和移除 |
| 选择同来源两个日期的条目 | 提醒重复，仍分别生成 |
| 一批生成部分失败 | 成功内容可阅读和复制，失败项可重试 |
| 修改提示词重新生成整份 | 得到新 Feed，原 Feed 保留 |
| 删除任务或收集条目 | 已有 Feed 的内容和来源依据不变 |
| 按原生指标排序 | 单平台可排序，跨平台无统一热度分 |

已确认视觉方向：白色为主、冷灰分区、蓝色强调；收集列表紧凑，Feed 阅读排版宽松。五页设计图见 [页面设计评审](design/README.md)，图稿已确认；生图是页面设计参考，不代表可运行界面。

页面衔接：点击任务查看其配置与收集记录，记录中的“查看条目”进入对应结果；点击收集条目查看完整来源信息。选材后进入生成页，完成后在“我的 Feed”查看成功或部分成功结果。重新生成整份回到提示词配置，保留对应素材，完成后形成新 Feed。设计图中的列表仅展示摘要字段，完整来源信息及依据通过详情查看。

最终评审检查：术语一致、入口与返回路径明确、两条流程独立、收集与生成分离、核心与异常状态完整、设计图与本文相符。huggon1 确认 PRD 质量后再提交并合并 PR。
